VI.13

Dictionary scope: global, request, block

Every dictionary is fit on something and shared by whoever uses it. That one choice — its scope — decides how well it predicts and what it costs, and it turns the cat-thread ladder into three rows of one table.

The forecaster at the harbour office plays a game with Gull Rock. Before each pressure reading arrives, she writes down a guess. If the station makes the same guess, it only has to radio how wrong it was — and a small error is cheap to send. She keeps three notebooks for this.

  • The almanac. Fifty years of averages for the whole coast. On 28 October the pressure is typically 1013 hPa. Printed once, owned by everybody, never rewritten.
  • The storm log. Notes she started when this storm arrived two days ago. It sits low, around 1005, and keeps falling.
  • The hour sheet. The last hour, reading by reading: 1001.2, 1001.0, 1000.9.

Each notebook is narrower than the one before, and each guesses better. Each is also more work. The almanac costs her nothing. A storm log must be written for every storm. The hour sheet is torn up and rewritten every hour. And the station has to keep identical copies of all of them, or its guesses will not match hers.

Three notebooks, three scopes

A KV dictionary faces the same choice. What it is fit on decides who can share it, and that choice is its dictionary scope. There are three, and they are exactly the three rungs of the cat-thread ladder.

ReminderThe cat-thread ladder (IV.11)

Take one entry from the Maine Coon part of a long cat_thread. Judged against everything a model could ever be asked, it is very surprising. Against the rest of cat_thread it is less so. Against the surrounding Maine Coon tokens it is least surprising of all. Global ⊃ thread ⊃ neighbourhood. See IV.11 The cat-thread ladder.

global scope“the Globe”this project's own words
  • Fit on: a calibration corpus, once, offline. Shared by: every request the GPU ever serves.
  • In the toy world: the almanac. On the ladder: rung 1, “everything a model could be asked”.
  • Cost: nothing at serving time. Catch: it knows only what all texts have in common.
request scope“the Thread”this project's own words
  • Fit on: one request’s own history (after prefill; refreshed now and then). Shared by: every entry of that request, at one layer.
  • In the toy world: the storm log. On the ladder: rung 2, “this is cat_thread”.
  • Cost: one load per request, when it is admitted.
block scope“the Brick”this project's own words
  • Fit on: one block of b consecutive tokens. Shared by: those b entries.
  • In the toy world: the hour sheet. On the ladder: rung 3, “the Maine Coon paragraphs around this entry”.
  • Cost: many dictionaries per request, which must sit on the GPU to be useful.
  • Easy to confuse with: request scope with a long block. A block as long as the request is the request.

The scopes are nested: global ⊃ request ⊃ block. Every entry sits in exactly one block, inside one request, inside the world. So every entry has three dictionaries that could predict it — slide the token in the figure and watch which ones change.

☞ Things to try
  1. Move the token across request 1. The global and request dictionaries stay the same; the block dictionary changes at every boundary.
  2. Raise b until it reaches L. Request 1 becomes one block: block scope has collapsed into request scope.
  3. Shrink b to 1K with L=128K. That is 125 block dictionaries per request per layer. Hold on to that number for the next section.
Takeaway
  • A dictionary’s scope is what it is fit on, and therefore who shares it: global (the Globe), request (the Thread) or block (the Brick).
  • The scopes are nested, global ⊃ request ⊃ block, and they are the three rungs of the cat-thread ladder.
  • Request scope is block scope with b=L.

What each scope costs

Narrower scope fits better, but it costs more dictionary bytes to store, to load and to keep on the GPU. The table counts those costs per request and per layer; memory is in entries’ worth, so w means “as much as w entries”. The last row keeps only nD​ dictionaries on the GPU, in a dictionary cache.

scope dictionaries crosses the link GPU memory
global 0 (one shared copy) never 0
request 1 once, at admission w
block, all resident ⌈L/b⌉ once, at admission ⌈L/b⌉w
block, cache ⌈L/b⌉ when a block turns busy nD​w

Plug in the reference setting (L=100K tokens, e=640 bytes, NL​=78 layers), with weights that are assumed for illustration.

  • Request scope, w=256: the load is 256×640 B×78≈12.8 MB. That is about one step’s worth of miss traffic (13.7 MB at B=4096, see III.11 Three numbers and a deadline), paid once per request.
  • Block scope, all on the GPU, b=4096: there are ⌈100K/4096⌉=25 blocks. With w=32 that is 800 entries’ worth per layer. With w=256 it is 6400 — more than the 4096 slots of the hot cache itself.
  • Block scope with a dictionary cache: only nD​ dictionaries stay, so memory is small. The price moves to the link: every newly busy block must have its dictionary loaded while it is busy.
Running themeSide information at both ends

A dictionary helps only if the GPU actually holds it when a miss arrives. Global scope gets that for free. Request scope pays once. Block scope pays again and again, either in GPU memory or in loads — the receiver must have the almanac, and narrow almanacs are many.

Also on I.4 · II.1 · II.5 · II.25 · IV.1 · IV.4 · V.13 · VI.8 · VI.17 · VII.9
Takeaway
  • Global costs nothing. Request costs one load per request (about 12.8 MB for w=256).
  • Block scope costs ⌈L/b⌉ dictionaries per request per layer: in GPU memory if all stay, in loads if only a few do.
  • Heavy block dictionaries cannot all stay resident; VI.15 The economics, written out works out what that does to requests per GPU.

Scope gains

The bits a narrower scope buys get their own names. Measure the rate in bpe for one dictionary type at each scope. A scope gain is the drop from one rung to the next:

greq​=what this conversation addsbpeglobal​−bperequest​​​,gblk​=what the neighbourhood addsbperequest​−bpeblock​​​(VI.13·1)
SymbolsWhat’s in this equation (3)
greq​
request-scope gain [bits per element] — Bits per element saved by a per-request dictionary over a global one (same dictionary type). VI.13
bpe
bits per element [bits] — Rate of a lossless code per 8-bit element, all costs included. Raw is 8. VI.1
gblk​
block-scope gain [bits per element] — Bits per element saved by per-block dictionaries over a per-request one — fallen-apple similarity at block scale. VI.13

Both compare the same type (loc against loc, KLT against KLT), so the difference is due to scope alone. Two facts frame them.

  • Their sign is a theorem; their size is not. Conditioning never increases entropy (IV.12 What the ladder gets right), so before paying for the dictionary both gains are at least zero. How large they are is exactly what nobody has measured.
  • gblk​ is the number this project bets on. It is fallen-apple similarity similarity at block scale, in bits. The distance curve of VIII.5 Framework A: bits versus distance is its finer-grained form.
ReminderThe exchange rate (II.12)

A predictor that explains a share R2 of the variance saves 21​log2​1−R21​ bits per element, for bell-shaped data.

Here is the variance budget of IV.14 The trap: the exchange rate is harsh (30 % global, 20 % thread, 20 % block, 30 % noise — illustrative), run through the exchange rate:

rung variance explained so far bits saved so far gain of this rung
global 30 % 0.26 —
request 50 % 0.50 greq​≈0.24
block 70 % 0.87 gblk​≈0.37

Two fifths of a bit per element, from a block rung that explains a fifth of all the variance. The synthetic dress rehearsal (VI.18 A synthetic dress rehearsal) measures the same two gains on data with a known recipe and finds about 0.10 and 0.16 bit — close to what the exchange rate predicts for that recipe.

Takeaway
  • greq​ and gblk​ are the bits per element saved by narrowing the scope one rung, for the same dictionary type.
  • They cannot be negative before the dictionary is paid for; after paying, they can.
  • gblk​ is fallen-apple similarity in bits. The next page asks how much of it the dictionary’s own size eats.
