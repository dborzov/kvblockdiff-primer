IX.7

Experiment 1b: the exact lossless ladder

1a promised; 1b pays in real bits. Every dictionary type, at every scope, in both 8-bit grids, with both rates and every tax — and every entry rebuilt bit for bit along the way.

Experiment 1a measured how much a cheap prediction could explain, in floats. Experiment 1b takes the same data, rounds it to 8 bits (IX.5 Step 0: the exact 8-bit target), and runs every dictionary type through the harness. Each number that comes out is a real, exact, fully charged rate.

The rungs and the scopes

The ladder has five rungs, from the lightest dictionary to the heaviest (VI.9 The four dictionaries side by side).

  1. loc — a location per channel. The cheapest; no per-entry tax.
  2. The KLT bound — computed from the eigenvalue spectrum, not coded. It says whether a lossless rotation would be worth building at all.
  3. KLT, rank 16, with explicit coefficients — an upper-cost stand-in for a lossless transform: 16 basis vectors in the dictionary, 16 coefficients in every delta.
  4. VQ — 256 centroids on 64-element pieces of the entry (a product quantizer). The heaviest dictionary.
  5. sib — predict an entry from its nearest sibling in the same block, leave-one-out. Almost no dictionary, but the noise doubles.

Each rung runs at global scope, request scope and block scope with b∈{512,2K,8K}; in E4M3 and INT8; with both rates; for keys and values of all six layers; and once more on shuffled data. Before running anything, it pays to see what each cell will cost in taxes alone.

☞ Things to try
  1. Switch to “dictionary share” and read the VQ row from right to left: 4.05, 1.01, 0.25, 0.06 bits. VQ at b=512 is not worth running.
  2. Switch to “per-entry tax”. KLT and VQ pay 0.125 bit per element at every scope — a tax that no block size amortizes.
  3. Find the loc row. Green everywhere: this is why loc goes first.
Takeaway
  • Five rungs × five scopes × two grids × two rates × keys and values × six layers — plus the shuffled twin.
  • The taxes alone rule out some cells (VQ at 512) before any data is touched.
  • Light dictionaries are free at every scope; heavy ones only at request scope or very large blocks.

The code

The source sketched 1b as two functions, rung and ladder. The harness keeps their shape and fixes what they left open. Scoring one block is one function; scoring a scope is another.

What changed against the source’s sketch, and why:

  • The fitting set decides the scope. A coder never knows its scope; the harness hands it calibration codes, a whole sequence or a block.
  • Every model is fit on the fitting set. The entropy model and the fixed-length widths see only what the dictionary saw.
  • Request scope has its own code path, so the scope-consistency control has something to compare (IX.3 Four controls, built before any real data).
  • The entropy model is grid-aware (grid-aware model), so the E4M3 column is not overcharged.
  • The predict-or-not flag is a coder of its own, PredictOrNot(Loc()): a wrapper that stores one bit per channel and passes the same round trip as everything else.
  • Solo coding is scored at global scope only. A “solo” fit per block would be loc in disguise, because the coder’s own model has a centre.

The shuffle control is one more function: entries are permuted across all evaluation sequences, each entry kept intact.

Takeaway
  • One function scores a block, one scores a scope; the fitting set is the only thing that makes scopes differ.
  • Every model is fit on the fitting set, every block is round-tripped, partial blocks are refused.
  • A rung is a small class; the harness does the rest.

What the run printed

On the synthetic set of IX.3 Four controls, built before any real data the harness prints one row per format, coder, data set and rate. Here are six of the rows for the loc dictionary with its flag, and the solo line:

How to read it:

  • g_req and g_blk are the scope gains greq​ and gblk​: global minus request, and request minus the best block.
  • The best block is 2048, the planted length, in every original row; after the shuffle the best “block” is the largest one and gblk​ is zero.
  • E4M3 starts lower (6.367 bits for solo coding against INT8’s 7.073 in the entropy rate): the log grid suits context-free coding. INT8 keeps more of the gain in the fixed-length rate. Both effects were predicted on paper (VI.11 The 8-bit grid gives and takes).

And one honest flaw. Solo coding’s fixed-length rate is exactly 8.0 bits in both formats. The plain fixed-length format cannot shorten raw codes that use the whole range, so against this baseline every dictionary looks good. A fair rung 0 for the fixed-length column splits off the exponent, as SplitZip does, and saves about a bit on its own. The harness does not have that rung yet; until it does, fixed-length gains over “solo” overstate what dictionaries add.

By the numbersHow long will the real ladder take?

The synthetic ladder (two coders, eight scope settings, original and shuffled, two formats) took 35–45 seconds on one CPU core. The real data is about 770 times larger per scope setting. Scaled linearly, a loc ladder is a few hours of single-core numpy — an estimate, not a measurement. VQ’s k-means is the slow rung and runs overnight.

Takeaway
  • On synthetic data the harness finds the planted block length and nothing after the shuffle.
  • E4M3 wins solo coding; INT8 keeps more of the dictionary gain in the fixed-length format.
  • The fixed-length column still lacks a fair solo baseline (exponent splitting); until then its gains are overstated.
