II.18

Codebooks versus rotations

A rotation and a codebook are two ways to exploit the same kind of redundancy. On lumpy data the codebook wins easily. On bell-shaped data it cannot win at all — a result from rate–distortion theory that saves a lot of wasted engineering.

Take the k-means of the last page and run it on the other cloud of this Part: the two thermometers, a single bell-shaped cigar with no clusters at all. With C=8 it lays its eight centroids along the diagonal, like beads on a string. It has found the long axis of the cigar — the KLT direction of II.15. And it charges an index for every reading to say which bead is nearest.

So a codebook can do a rotation’s job. Can it do it better? This page says when it can, when it cannot, and why.

Two ways to use the same redundancy

Rotation versus codebook
KLT — the Compass
  • Keeps: one rotation (a d×d table), sent once.
  • Per vector: nothing extra. Every vector is rotated the same way.
  • Sees: straight-line structure — correlation between channels.
  • Blind to: clusters, curves, anything a covariance matrix does not record.
VQ — the Hive
  • Keeps: C centroids, sent once.
  • Per vector: an index, log2​C bits — the index tax.
  • Sees: any lumpy shape, clusters included.
  • Pays for: every bit of structure it captures, one index at a time.

The figure runs the contest on both clouds of this Part, for codebooks from 2 to 64 centroids.

What the bars say:

  • The thermometers (bell-shaped). The rotation saves 1.47 bits per element for free. The codebook’s net climbs with C — 0.23 at C=2, 0.73 at 4, 1.07 at 8, 1.36 at 64 — and never reaches the rotation. Each doubling of C buys a little more saving and charges half a bit more tax.
  • The weather regimes (clustered). The rotation saves 0.05 bit; it cannot see islands. The codebook nets 1.46 bits at C=3 and stays around that level as C grows.

The estimate is rough in one way that favours the rotation: the Gaussian rule slightly overstates the cost of the flat-topped residuals that VQ leaves behind. The next section shows that no fairer accounting changes the verdict on bell-shaped data.

Takeaway
  • A codebook can rediscover a rotation, but it pays an index for every vector to do so.
  • On the bell-shaped thermometer cloud the KLT wins (1.47 against at most 1.36 bits per element).
  • On the clustered regimes VQ wins (1.46 against 0.05).

Why a codebook cannot win on bell-shaped data

There is a branch of information theory about exactly this trade-off: how many bits you spend against how much error you leave.

rate–distortioninformation theory
  • What it is: the theory of the best possible trade-off between the bits spent describing data (the rate) and the error left over (the distortion).
  • Its key result for bell-shaped data: describing a Gaussian value of variance σ2 with a given number of bits leaves an error variance of at least σ2⋅2−2×bits. Each bit can, at best, halve the error’s standard deviation.
  • Why we care: it gives bounds before building anything.

Apply it to a codebook. The index is log2​C bits per vector, which is log2​C/d bits per element. At best, it shrinks each element’s error standard deviation by 2log2​C/d, so the residual saves at most log2​C/d bits per element:

what the centroid saves (beyond the rotation)21​log2​residual varianceσ2​​​≤index taxdlog2​C​​​(II.18·1)
SymbolsWhat’s in this equation (3)
σ
standard deviation [same as the value] — Typical distance from the mean; σ2 is the variance. II.11
C
codebook size [centroids] — Number of centroids in a VQ codebook; naming one costs log2​C bits. II.17
d
dimension [elements] — Number of elements in a vector (an entry has d elements; 640 in the reference setting). II.13

On Gaussian data the gain beyond what the rotation already gets is at most the tax. The net is at most zero, with equality only for an ideal codebook; k-means is not ideal. That is the gap in the figure.

DetailThe same verdict, from a counting argument

The index is computed from the reading, so it contains nothing the reading did not. Sending the index and then the residual therefore costs at least as many bits as the reading’s own entropy, H(X). For bell-shaped data, a rotation followed by coding each axis on its own already gets down to H(X). A codebook can at best tie. On clustered data a rotation stays well above H(X), and that is the room a codebook can win.

The first draft of this proposal checked the same thing by Monte Carlo in a harder setting: 64 elements per vector, one block of 16,384 vectors, k-means codebooks charged for both the index and the codebook itself. On correlated Gaussian data, VQ netted +0.17 to +0.25 bit per element against +0.50 for the rotation. On data with 32 real clusters, VQ netted +1.5 bits against +0.68. The same verdict as our two-dimensional toy, in more dimensions.

CarefulWhat this does not say

It does not say codebooks are useless. It says they earn their keep only where the data is lumpy. Whether a particular kind of data is lumpy is a question for measurement, not for instinct. Part VII returns to the first draft’s instinct “VQ, then entropy-code the error” (VII.5 "VQ, then entropy-code the error" cannot beat a rotation on Gaussian data).

Takeaway
  • Rate–distortion: each bit can at best halve a Gaussian error’s standard deviation.
  • So on bell-shaped data a codebook’s extra saving is at most its index tax: it cannot beat the untaxed rotation.
  • Only lumpy (clustered) data gives a codebook room to win.

Product quantization

Big codebooks are expensive to store and slow to search. With 64 elements per vector, an index budget of 64 bits would mean 264 centroids. The standard escape is to split the vector.

product quantizationcoding & compression
  • What it is: cut each vector into nsub​ pieces and give each piece its own small codebook. A vector is described by nsub​ indices, one per piece.
  • Example: 64 elements, nsub​=8 pieces of 8 elements, 256 centroids per piece. The index tax is 8×log2​256=64 bits per vector, 1 bit per element. The codebooks hold 8×256×8=16,384 numbers, while the combinations act like 2568=264 centroids.
  • Same economics: each piece is an ordinary codebook facing the same bound. Product quantization makes VQ affordable; it does not make it beat a rotation on bell-shaped data.
ConnectionThe family bill

Every member of the codebook family pays per vector: plain VQ pays log2​C, product quantization pays nsub​log2​256. The rotation pays once, for its table, and nothing per vector. Only data the rotation cannot describe justifies the per-vector tax.

Takeaway
  • Product quantization splits a vector into nsub​ pieces, each with its own small codebook.
  • It makes huge effective codebooks cheap to store, but the index tax and the bound apply piece by piece.
