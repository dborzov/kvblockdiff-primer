Glossary

Every term on this site, grouped by kind. Each chip links to the page where the term is defined; hovering it anywhere on the site shows the same reminder.

The signature terms of this project carry an emblem and a colour of their own. The other terms are tinted by their category.

information theory

bit
bit
The answer to one yes/no question; the unit of information. With n bits you can tell apart 2n equally likely possibilities.
conditional entropy
conditional entropy H(X | Y)
The average number of bits still needed to describe X when Y is already known. Never more than H(X), on average.
cross-entropy
cross-entropy
The average bits per symbol you pay when you code data with a model that is not exactly the data’s true distribution. Always at least the entropy; the gap is the price of a wrong model.
entropy
entropy H
The average surprisal of a source, H, in bits per symbol — the fewest bits per symbol any lossless code can average.
mutual information
mutual information I(X; Y)
How many bits knowing Y saves when describing X, I(X;Y)=H(X)−H(X∣Y). Also called redundancy or, loosely, similarity — all three are the same number of bits.
order-0 entropy
order-0 entropy (context-free entropy)
The entropy computed from symbol frequencies alone, ignoring any context such as the previous symbols. The best a code can do if it looks at each symbol in isolation.
perplexity
perplexity
2H — entropy expressed as an “effective number of equally likely choices”. Popular for language models; this site uses bits because bits × size = bytes on a wire.
probability
probability p
How often an outcome happens in the long run, a number p between 0 and 1. All outcomes’ probabilities add up to 1 (their distribution).
rate–distortion
rate–distortion theory
The theory of the best trade-off between how many bits you spend and how much error you accept. For Gaussian data it gives hard bounds that tell us when a codebook cannot win.
redundancy
redundancy
The bits a message spends on things the receiver could have predicted. Removing redundancy is what every compressor does.
side information
side information
Something the receiver already knows that is relevant to the message (an almanac, a dictionary). It makes the message cheaper to send, by exactly the mutual information.
Slepian–Wolf
Slepian–Wolf coding (side information only at the decoder)
The 1973 theorem that X can be sent losslessly at H(X∣Y) bits even when only the receiver knows Y — the sender groups messages into bins and the receiver uses Y to pick the right member. Its lossy sibling is Wyner–Ziv coding.
surprisal
surprisal (self-information)
How surprising one outcome is, in bits, −log2​p. Rare outcomes carry many bits; certain outcomes carry none. An ideal code spends exactly this many bits on the outcome.

coding & compression

VQ
vector quantization (VQ) · “the Hive”
Describe each vector by the index of the nearest of C reference vectors (centroids) in a codebook. Losslessly, the index is a prediction and the exact residual is stored too; the index costs log2​C bits per vector.
amortization
amortization
Spreading a one-time cost over everything that shares it. A dictionary of w entries’ worth shared by b entries costs 8w/b bits per element.
arithmetic coding
arithmetic coding
An entropy coder that codes a whole message as one number in a shrinking interval, so symbols can cost fractions of a bit. Near-ideal, but sequential: you must decode from the start.
code
code and codeword
A rule that turns each symbol into a string of bits (its codeword) and back. A prefix code is one where no codeword starts another, so a stream of codewords can be read without separators.
codebook
codebook
The list of C reference vectors (centroids) used by vector quantization. On this site “codebook” means only this; the general word is dictionary.
context modelling
context modelling
Instead of subtracting a prediction, use it as context — pick the probability table for the value based on the prediction. It can never do worse than ignoring the prediction, but it is not fixed-length.
entropy coder
entropy coder
Any coder that spends about −log2​p bits on a symbol of probability p, so its average rate approaches the entropy. Huffman, arithmetic coding and rANS are entropy coders.
escape
escape (and the escape stream)
A value too big for the fixed width is “escaped” — marked, and stored separately in full, in an escape stream of (position, raw value) pairs. Rare escapes keep the common case short.
fixed-length code
fixed-length code
Every value gets the same number of bits, n. Wasteful compared with an entropy coder, but any value’s position is known in advance, so decoding is trivially parallel and random access is free.
grid-aware model
grid-aware entropy model
An entropy model that describes the value, not the code number: a Laplace bump in value units, centred on the prediction, whose probability for each 8-bit code is the area over that code’s grid cell. Needed on E4M3, where a single bump in index space fits badly.
Huffman code
Huffman code
The best prefix code for known symbol probabilities, built by repeatedly merging the two rarest symbols. Codeword lengths are whole bits, close to each symbol’s surprisal.
index tax
index tax (the cost of naming a centroid)
The log2​C bits per vector that vector quantization spends to say which centroid was used. A codebook helps only if it saves more bits than this.
lossless
lossless compression
Compression after which the original is rebuilt exactly, bit for bit. The opposite, lossy compression, keeps only an approximation.
lossy
lossy compression
Compression that throws some detail away for good and rebuilds only an approximation (JPEG photos, 2-bit KV quantization). This project is lossless.
LZ matching
LZ matching (Lempel–Ziv)
The trick at the heart of zip and zstd: when a string of bytes has appeared before, write “copy n bytes from k bytes back” instead of the bytes themselves.
prediction
prediction and predictor
A guess x^ of the next value made only from things the receiver also knows. The rule that makes the guess is the predictor.
predictive coding
lossless predictive coding (DPCM)
Predict each value from what is already known, store the exact integer residual, entropy-code the residual. Lossless audio (FLAC), lossless images (PNG filters) and this project all have this shape.
product quantization
product quantization (PQ)
Split each vector into nsub​ pieces and give each piece its own small codebook. Much larger effective codebooks for the same storage; the same economics as plain VQ.
random access
random access
Being able to decode any single item on its own, without decoding what came before it. Stream coders (zstd, arithmetic coding) give it up; fixed-length codes keep it.
rANS
rANS (range asymmetric numeral systems)
A modern entropy coder with arithmetic coding’s near-ideal rates and much faster decoding. Like arithmetic coding, it keeps a running state, so a stream decodes front to back.
residual
residual
The exact difference between a value and its prediction, r=x−x^. In lossless coding it is an integer and is stored exactly; good predictions give small residuals that cost few bits.
trained dictionary
trained dictionary (zstd)
A zstd dictionary built from a sample of typical records and given to both sender and receiver in advance, so that even a single small record compresses as if the compressor had seen its siblings.
transform coding gain
transform coding gain
The bits saved per element by rotating data to its KLT axes before coding, 21​log2​(AM/GM) of the eigenvalues. Large only when a few directions hold most of the spread.
zstd
Zstandard (zstd)
A widely used general-purpose lossless compressor. It replaces repeated byte strings with short references to an earlier copy and entropy-codes the rest; it can be primed with a trained dictionary.

statistics

centroid
centroid
The average point of a group of vectors; the representative stored in a codebook.
covariance
covariance and correlation
How much two channels move together. Correlation is covariance rescaled to −1 … +1. Correlated channels can partly predict each other.
distribution
probability distribution
The list of all possible outcomes together with their probabilities. A histogram of real data is an estimate of it.
Gaussian
Gaussian (normal) distribution
The bell curve. Sums of many small independent effects look Gaussian. For a given spread it is the most unpredictable shape, so it is the honest worst case.
histogram
histogram
A count of how often each value (or range of values) occurs in a sample; the measured estimate of a distribution.
k-means
k-means clustering
The standard way to fit a codebook — alternately assign every vector to its nearest centroid and move each centroid to the average of its vectors, until nothing changes.
Laplace
Laplace distribution
A sharper, pointier cousin of the bell curve (two exponential tails) with scale β. Prediction residuals usually look like this, so coders model them with it.
mean
mean μ
The average value, μ. Subtracting it is the simplest prediction of all.
Monte Carlo
Monte Carlo simulation
Checking a claim by simulating many random samples on a computer and measuring, instead of (or as well as) deriving it with formulas.
R²
R² (fraction of variance explained)
The share of a value’s variance that a predictor accounts for, R2 between 0 and 1. The residual keeps variance (1−R2)σ2.
standard deviation
standard deviation σ
The typical distance of a value from the mean, σ. Halving it saves one bit per value for bell-shaped data.
standardize
standardizing a channel
Subtract a channel’s mean and divide by its standard deviation, so every channel has mean 0 and spread 1 and channels measured in different units can be compared.
variance
variance σ²
The average squared distance from the mean, σ2 — how spread out values are. Its square root σ is the standard deviation.

vectors & linear algebra

KLT
Karhunen–Loève transform (KLT) · “the Compass”
The rotation of the axes that lines them up with the directions in which the data spreads most (the same thing as PCA). After it, the coordinates are uncorrelated and can be coded one by one with no loss of efficiency.
AM/GM
arithmetic mean over geometric mean
The ratio of the ordinary average of the eigenvalues to their geometric average. It is 1 when all are equal and grows when a few dominate; 21​log2​ of it is the transform coding gain.
channel
channel (one element position, across many vectors)
One fixed position c inside a vector, looked at across many vectors — like one sensor’s column in a table of readings. ‘Per-channel’ statistics are computed separately for each position.
covariance matrix
covariance matrix
The d×d table of covariances between every pair of channels. Its eigenvectors are the KLT axes and its eigenvalues the spreads along them.
eigenvalue
eigenvectors and eigenvalues
For a covariance matrix, the eigenvectors are the natural axes of the data cloud and the eigenvalue λ of each is the variance along it.
lifting
lifting (integer-reversible transforms)
A way to split a rotation into a few integer “shear” steps, each exactly reversible, so a transform can be lossless on integers. Used in lossless JPEG 2000.
low rank
low rank
Data whose spread lives mostly in a few directions (a few large eigenvalues, the rest small). The sharper the drop, the more a KLT saves.
PCA
principal component analysis (PCA)
The statistics name for the KLT — rotate to the directions of greatest spread. Same mathematics, different tradition.
PLUS factorization
PLUS factorization (a rotation as integer-reversible steps)
Writing a matrix as a reordering of its rows (P) times three triangular factors (L, U, S) whose diagonals hold only ones when the matrix is a rotation. Each factor can be applied to integers with rounding and undone exactly, so any rotation becomes a lossless integer transform — lifting for whole matrices.
rotation
rotation (change of basis)
Describing the same points with a different set of perpendicular axes. Nothing about the data changes; only which numbers we write down.
sparse coding
sparse coding (a vector as a few atoms of a large dictionary)
Describe a vector as a weighted sum of a few vectors (“atoms”) picked from a large, fixed dictionary, and store only which atoms and their weights. VQ is the special case of one atom with weight 1; a KLT uses every axis with a weight.
vector
vector
An ordered list of d numbers, e.g. one weather reading (temperature, humidity, …) or one entry. Each number is an element.

number formats

BF16
bfloat16 (BF16)
A 16-bit floating-point format with 8 exponent bits and 7 mantissa bits — the usual working format of language models.
exponent
exponent and mantissa
In a floating-point number, the exponent picks the power of two (the “binade”) and the mantissa picks the position inside it. In model data the exponent is predictable and the low mantissa bits are close to noise.
floating point
floating point (sign, exponent, mantissa)
Numbers stored as sign × mantissa × 2^exponent. Spacing between neighbours grows with size, so relative precision is constant and the grid is logarithmic.
FP8
8-bit floating point (E4M3, E5M2)
8-bit floats. E4M3 has 4 exponent and 3 mantissa bits (values up to 448), E5M2 has 5 and 2. Where KV-cache storage is heading.
index space
index space (counting grid steps)
Number the representable values of a format in order, …, −1, 0, 1, …, and work with those integer indices. A residual of 1 then means “one grid step”, however big the step is.
INT8
INT8 with a scale (a uniform grid)
Store x as the nearest integer to x/scale, between −127 and 127. Representable values are evenly spaced, so differences behave as in ordinary arithmetic.
quantization
quantization (rounding to a grid)
Rounding numbers to the nearest point of a fixed grid of representable values. Done once, it defines the exact values our lossless coder must reproduce.
scale group
scale group (numbers that share one rounding ruler)
The set of numbers that are rounded with one shared ruler — one smallest value and one step size. Per-channel rounding makes each scale group one channel over a run of tokens (a column); per-token rounding makes it one token’s vector (a row).

memory, caches & hardware

HiSparse
HiSparse (Xie et al., 2026) · “the Two-tier Library”
The production system we build on. It keeps each request’s full KV history in host memory and a small least-recently-used hot cache of raw entries per layer on the GPU. Model outputs are unchanged.
hot cache
hot cache (HiSparse's per-layer GPU buffer) · “the Hearth”
HiSparse’s small buffer of B raw entries per request per layer, kept in GPU memory and managed least-recently-used. Entries found there are hits; the rest are misses fetched from host memory.
bandwidth
bandwidth and latency
Bandwidth is how many bytes per second a link carries once data flows; latency is how long one request takes to start arriving. Many tiny scattered reads hurt both.
Bélády
Bélády's optimal policy
The clairvoyant eviction policy — evict the item whose next use is furthest in the future. Impossible in practice, but it bounds what any policy could achieve.
cache
cache
A small, fast memory that keeps copies of some items from a big, slow one. A request found in it is a hit; otherwise a miss, and the item must be fetched.
data path
data path (where compressed KV bytes travel, and how they are read)
Where a compressed KV cache travels and how it is read back: a bulk transfer between machines, a network fetch of a stored prefix, the GPU-resident footprint, or the sparse-decode miss path of scattered single-entry reads. The path, more than the statistics, decides what a codec may look like.
disaggregated serving
disaggregated serving (prefill and decode on separate GPUs)
Running the prefill of a prompt and the decoding of its answer on different GPUs or machines. The finished KV cache of the prompt must then be shipped from the prefill side to the decode side, in one bulk transfer per request.
eviction
eviction
Removing an item from a full cache to make room for a new one. The eviction policy decides which item goes.
HBM
HBM (GPU memory)
High-bandwidth memory stacked next to the GPU — very fast, small (tens of GB) and expensive. The hot cache lives here.
hit / miss
hit and miss
A hit is a request served from the cache; a miss must fetch the item from slower memory. The miss rate m is the fraction of requests that miss.
host DRAM
host memory (DRAM)
The CPU’s main memory — much larger than HBM, much slower to reach from the GPU. HiSparse keeps the full KV history here.
LRU
least recently used (LRU)
The eviction policy that throws out the item whose last use was longest ago. Simple, and very good when recent use predicts future use.
miss-rate curve
miss-rate curve m(B)
The miss rate of an LRU cache as a function of its size B. One curve, read off the reuse distances, gives the miss rate at every size.
PCIe
PCIe link
The wire between host memory and the GPU. PCIe Gen5 ×16 carries about 64 GB/s each way (≈50 in practice) — roughly 100× less than HBM.
reuse distance
reuse distance (stack distance)
For a request, the number of distinct other items requested since this item’s previous request. Under LRU with B slots, a request misses exactly when its reuse distance is at least B.
trace replay
trace replay (re-running caches on recorded selections)
Recording which entries the (proxy) indexer selects at every decode step, then re-running the hot cache and the dictionary cache on that list. It measures miss rates, the δ-miss fraction and dictionary loads without running any kernel.

transformers & attention

indexer
indexer (the selector of sparse attention) · “the Scout”
A cheap scorer that, at every layer and every decode step, looks over all past positions and picks the k that attention will read. Its picks are announced before any KV bytes are touched.
attention
attention (query, key, value)
The step where a token looks back. Its query vector is compared with every stored key; the scores become weights; the output is the weighted mix of the stored values.
DSA
DeepSeek Sparse Attention (DSA)
The top-k sparse attention of DeepSeek-V3.2 (also used by GLM-5.x), with a small trained “lightning indexer” that scores every past token cheaply.
head
attention head and GQA
Attention is split into several heads that work in parallel on slices of the vectors. With grouped-query attention (GQA) several query heads share one key/value head, which shrinks the KV cache.
KV cache
KV cache
The stored keys and values of every previous token at every layer, kept so they need not be recomputed at each decode step. It grows by one entry per layer per token.
layer
layer
One of the NL​ stacked processing stages of a transformer. Each layer has its own attention and its own part of the KV cache.
MLA
multi-head latent attention (MLA)
DeepSeek’s variant of attention that stores one compressed latent vector per token per layer instead of separate keys and values. Still one fixed-size entry per position.
prefill / decode
prefill and decode
Prefill reads the whole prompt at once; decode then generates the answer one token per step, each step reading everything stored so far.
proxy model
proxy model (a small open model standing in for the real target)
The small open model whose KV cache wave 1 measures in place of the real sparse-attention target: Qwen3.5-2B’s full-attention layers, replicated on Qwen3-1.7B. It fits a 16 GB GPU; whether its statistics transfer is itself a risk.
RoPE
rotary position embedding (RoPE)
The way many models tell attention where a token sits — by rotating pairs of key and query channels by an angle that grows with the position. Keys are more regular before this rotation than after it.
sparse attention
top-k sparse attention
Attention that reads only k selected past entries per layer per step (chosen by an indexer) instead of all of them. Compute stops growing with context; storage does not.
token
token
The unit of text a language model reads and writes — a word or a piece of one. A model generates one token per decode step.
TPOT
time per output token (TPOT)
How long one decode step takes for a request — 30 ms in the reference setting. Every byte moved per step must fit into this time.

this project's own words

block
block (b consecutive entries of one request at one layer) · “the Row”
b consecutive tokens’ entries of one request at one layer. A design knob of the algorithm (we choose b), not a property of the data.
block scope
block scope (one dictionary per block) · “the Brick”
A dictionary per block of b tokens. Fits the local neighbourhood best, but there are many of them per request and they must be cached on the GPU.
cat-thread ladder
the cat-thread ladder (the intuitive argument) · “the Ladder”
The intuitive argument for the project — an entry is less surprising against its thread than against everything, and least surprising against its own neighbourhood. Right in direction, leaky in its evidence, and harsh in its exchange rate.
compressibility curve
the delta–dictionary compressibility curve · “the Arch”
For one algorithm at one block size, the points (dictionary cost per entry, delta size per entry) it reaches as its settings vary. The lower envelope over all algorithms is the roofline the data allows.
delta
delta δ (what is left to send once the dictionary is known) · “the Remainder”
The bytes needed to rebuild one item exactly, given its dictionary. For a KV entry, its size is ∣δ∣=ρe.
dictionary
dictionary (side information shared by many items) · “the Almanac”
Information shared by many items and sent to the receiver once, so that each item can be sent as a short delta instead. A zstd trained dictionary, a codebook and a set of per-channel means are all dictionaries.
dictionary cache
dictionary cache (kv-blockdiff's resident dictionaries) · “the Bookshelf”
kv-blockdiff’s per-layer set of nD​ block dictionaries kept in GPU memory. A miss in a block whose dictionary is on this shelf can be served by a delta.
entry
entry (one token's KV numbers at one layer) · “the Tile”
All the key and value numbers of one token at one layer, El,t​, of size e bytes. The unit the indexer selects, the cache moves and our coder must rebuild.
fallen-apple similarity
KV's fallen-apple similarity · “the Apple”
Hypothesis: an entry is cheaper to store exactly given an entry of the same layer a small token distance Δ away, and the closer the neighbour the cheaper. A curve over Δ, not a threshold. ‘The apple does not fall far from the tree.’
global scope
global scope (one dictionary for all requests) · “the Globe”
A dictionary fit once, offline, on a calibration corpus and shared by every request. Free at serving time; captures only what all texts have in common.
heavy block
heavy block · “the Anvil”
A block that holds many of the current step’s selections. If selections pile into a few heavy blocks for many steps, keeping their dictionaries on the GPU is cheap.
kv-blockdiff
kv-blockdiff (this project's proposal) · “the Delta Store”
Store a long KV history as per-block dictionaries plus tiny per-entry deltas, so that a cache miss moves a delta instead of a raw entry and the GPU rebuilds the entry bit for bit.
loc
location dictionary (loc) · “the Anchor”
The lightest dictionary: for each channel, a typical value (location) and spread (scale). Predict each element by its channel’s location; store the exact difference. Costs about 2 entries’ worth, no per-entry tax.
Lucky Louis property
the Lucky Louis property of the indexer · “the Gambler”
From one decode step to the next, the indexer re-selects mostly the same positions, so a cache that bets on last round’s winners keeps winning. It is about WHICH entries are wanted, not about their bytes.
neighbour similarity
KV's neighbour similarity (umbrella term) · “the Neighbours”
The family of hypotheses that an entry costs fewer bits to store exactly when a neighbouring entry (along some axis of the KV tensor) is already known. Members: fallen-apple (token axis) and upstairs (layer axis).
raw miss
raw miss (a miss served by the raw entry) · “the Crate”
A hot-cache miss whose block dictionary is not resident, so the full raw entry (e bytes) crosses the link, exactly as in HiSparse today.
reference setting
reference setting (the frozen numbers for all napkin math) · “the Pin”
One fixed rig used for every estimate: HiSparse’s GLM-5.1 deployment converted to 8-bit storage — 78 sparse layers, top-2048 selection, 100K-token context, 0.64 KB entries, 30 ms per token, a 50 GB/s link, 30 GB of GPU memory for KV.
request scope
request scope (one dictionary per request) · “the Thread”
A dictionary fit on one request’s own history, loaded once when the request is admitted. Captures what is special about this conversation.
sib
sibling dictionary (sib) · “the Twin”
Use another entry of the same block (the nearest “sibling”) as the prediction, plus a pointer to it. Cheap side information, but the residual is the difference of two noisy vectors, so its noise doubles.
solo
solo coding (rung 0, no dictionary) · “the Hermit”
Coding each entry by itself with one fixed, global, context-free code (per-channel histograms fit once on a calibration corpus). Worth about 1.1–1.3× on 8-bit KV. The baseline every dictionary must beat.
upstairs similarity
KV's upstairs similarity · “the Staircase”
Hypothesis: the entry of the same token one layer up is partly predictable from the entry below it. Layers are the floors of a building; tokens run along each floor.
victim tier
victim tier (a GPU tier of evicted entries' deltas) · “the Lifebuoy”
A second GPU tier holding the deltas of entries just evicted from the hot cache. If one of them is selected again it is rebuilt on the GPU instead of being fetched over the link.
δ-miss
δ-miss (a miss served by a delta) · “the Feather”
A hot-cache miss whose block dictionary is resident, so only the delta (ρe bytes) crosses the link and the GPU rebuilds the entry.
big-picture question
big-picture question (Q1–Q3)
An open-ended question the project exists to get closer to — Q1 (is there neighbour similarity?), Q2 (can a store use it?), Q3 (do misses pile into few blocks?). Too wide to answer with one experiment.
bpe
bits per element (bpe)
The rate of a lossless code in bits per 8-bit element, everything included (residuals, per-entry tax, amortized dictionary). Raw storage is 8; ρ=bpe/8.
calibration set
calibration set (data kept apart for the global scope)
Sequences kept apart from the evaluation data. Every global-scope dictionary and model is fit on them. If they overlap the evaluation data, the global scope cheats; if they are too few, the global dictionary is poorly fit and the request-scope gain looks bigger than it is.
decision rule
the decision rule of wave 1
The table, written before any data, that maps wave 1’s two scope gains greq​ and gblk​ to what happens next: block scope, request scope, a cost-model decision, or a published negative.
delta ratio
delta ratio ρ
ρ=∣δ∣/e — how much a miss shrinks. For 8-bit storage ρ≈bpe/8 (the rate also counts the amortized dictionary, which is not part of the delta).
dictionary scope
dictionary scope
What a dictionary is fit on and shared by — global (all requests), request (one conversation) or block (b tokens). The one axis that organizes the whole design space.
dictionary weight
dictionary weight w
A dictionary’s size measured in entries’ worth, w, so it is ∣D∣=we bytes. Amortized over a block it costs 8w/b bits per element.
entropy rate
entropy rate (the scientific number)
The rate an ideal entropy coder would reach on the residuals, plus the per-entry tax and the amortized dictionary. What arithmetic coding or rANS would achieve.
fixed-length rate
fixed-length rate (the engineering number)
The rate of a fixed-length code with escapes on the residuals, plus the per-entry tax and the amortized dictionary. What a fast GPU decoder achieves, and directly the delta size of the store.
framework question
experiment-framework question (A–D)
A question asked together with its measuring set-up — what is varied, what is held fixed, how every byte is charged — and with each possible outcome and its meaning written down before any data. Frameworks A–D.
harness
the measurement harness
The small program that runs every dictionary algorithm through the same interface, charges every byte by the same rule, runs the controls and plots the results.
lever
the two levers (cheaper misses, cheaper slots)
Lever 1 makes misses cheaper (move ρe instead of e over the link); lever 2 makes hot-cache slots cheaper (store heavy blocks as deltas in GPU memory).
per-entry tax
per-entry tax (side information sent with every entry)
Bits a dictionary coder must store with every single entry on top of its residual: which centroid (log2​C bits), which sibling (log2​b bits), a flag. Spread over the entry’s d elements it is the tax of the accounting.
roofline
roofline (of the compressibility curve)
The lower envelope of the compressibility curves of all algorithms tried — the best trade-off between dictionary cost and delta size that the data allows.
scope gain
scope gains g_req and g_blk
The bits per element saved by narrowing the scope one rung — from global to request (greq​) and from request to block (gblk​), for the same type of dictionary.
shuffle control
shuffle control
Rerun the measurement after shuffling tokens across sequences. Any gain that depends on neighbours being neighbours must vanish; a gain that survives is a bug.
δ-miss fraction
δ-miss fraction f_D
fD​, the share of misses that are δ-misses (their dictionary was resident). Decided by the residency policy and by where misses land.
