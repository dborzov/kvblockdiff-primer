XII.2

Glossary

Every term on this site, grouped by kind. Each chip links to the page where the term is defined; hovering it anywhere on the site shows the same reminder.

The signature terms of this project carry an emblem and a colour of their own. The other terms are tinted by their category.

information theory

bit
bit
The answer to one yes/no question; the unit of information. With n bits you can tell apart 2n equally likely possibilities.
code-length estimate
code-length estimate
The code length a probability table would reach, computed exactly on the data without building the compressor; a lead, not a result. The campaigns’ exact-computation numbers.
conditional entropy
conditional entropy H(X | Y)
The average number of bits still needed to describe X when Y is already known. Never more than H(X), on average.
cross-entropy
cross-entropy
The average bits per symbol you pay when you code data with a probability table that is not exactly the data’s true distribution. Always at least the entropy; the gap is the price of a wrong table.
delta share
delta share
The bytes of every delta of the punnet, summed, over the punnet’s raw bytes, ρ, empty deltas included; one of the two terms of the MDL ratio and not a score on its own. For 8-bit storage it is the bits per element of the deltas alone, divided by 8. The number a miss on the link cares about.
dictionary share
dictionary share
The dictionary’s bytes over the punnet’s raw bytes, xD​=w/b; one of the two terms of the MDL ratio and not a score on its own. It does not measure shared information: a compressor may file reference cherries in the dictionary or in deltas and the ratio barely moves.
entropy
entropy H
The average surprisal of a source, H, in bits per symbol: the fewest bits per symbol any lossless code can average.
MDL ratio
MDL ratio
(dictionary bytes + every delta’s bytes, summed) ÷ raw bytes of the punnet, so the dictionary share plus the delta share, xD​+ρ. 1.0 means no compression; 8 × the ratio is bits per element. The only score; neither share is one on its own.
mutual information
mutual information I(X; Y)
How many bits knowing Y saves when describing X, I(X;Y)=H(X)−H(X∣Y). Also called redundancy or, loosely, similarity: all three are the same number of bits.
order-0 entropy
order-0 entropy (context-free entropy)
The entropy computed from symbol frequencies alone, ignoring any context such as the previous symbols. The best a code can do if it looks at each symbol in isolation.
perplexity
perplexity
2H: entropy expressed as an “effective number of equally likely choices”. Popular for language models; this site uses bits because bits × size = bytes on a link.
probability
probability p
How often an outcome happens in the long run, a number p between 0 and 1. All outcomes’ probabilities add up to 1 (their distribution).
punnet redundancy
punnet redundancy (shared information per element)
The bits per element that the cherries of a punnet share: the sum of their solo entropies minus their joint entropy, per element. The most any per-punnet compressor can save over solo coding.
rate–distortion
rate–distortion theory
The theory of the best trade-off between how many bits you spend and how much error you accept. For Gaussian data it gives hard bounds that tell us when a codebook cannot win.
redundancy
redundancy
The bits a message spends on things the receiver could have predicted. Removing redundancy is what every compressor does.
side information
side information
Something the receiver already knows that is relevant to the message (an almanac, a dictionary). It makes the message cheaper to send, by exactly the mutual information.
Slepian–Wolf
Slepian–Wolf coding (side information only at the decoder)
The 1973 theorem that X can be sent losslessly at H(X∣Y) bits even when only the receiver knows Y: the sender groups messages into bins and the receiver uses Y to pick the right member. Its lossy sibling is Wyner–Ziv coding.
surprisal
surprisal (self-information)
How surprising one outcome is, in bits, −log2​p. Rare outcomes carry many bits; certain outcomes carry none. An ideal code spends exactly this many bits on the outcome.

coding & compression

compressor
compressor (one concrete compress/decompress pair) · “the Press”
One concrete pair of functions, deltas, dictionary = compress(punnet) and decompress(delta, dictionary), built as a dataflow graph of stages. The campaigns wrote 126 of them.
VQ
vector quantization (VQ) · “the Hive”
Describe each vector by the index of the nearest of C reference vectors (centroids) in a codebook. Losslessly, the index is a prediction and the exact residual is stored too; the index costs log2​C bits per vector.
amortization
amortization
Spreading a one-time cost over everything that shares it. A dictionary of w cherries’ worth shared by b cherries costs 8w/b bits per element.
arithmetic coding
arithmetic coding
An entropy coder that codes a whole message as one number in a shrinking interval, so symbols can cost fractions of a bit. Near-ideal, but sequential: you must decode from the start.
bit-field split
bit-field split (sign and exponent one way, mantissa another)
A stage that separates the bit fields of each FP8 element and routes them to different parts of the compressor’s graph: the predictable sign and exponent to a predictor and entropy coder, the noisy mantissa to a cheaper path.
code
code and codeword
A rule that turns each symbol into a string of bits (its codeword) and back. A prefix code is one where no codeword starts another, so a stream of codewords can be read without separators.
codebook
codebook
The list of C reference vectors (centroids) used by vector quantization. On this site “codebook” means only this; the general word is dictionary.
context modelling
context modelling
Instead of subtracting a prediction, use it as context: pick the probability table for the value based on the prediction. It can never do worse than ignoring the prediction, but it is not fixed-length.
entropy coder
entropy coder
Any stage that spends about −log2​p bits on a symbol of probability p, so its average rate approaches the entropy. Huffman, arithmetic coding and rANS are entropy coders.
escape
escape (and the escape stream)
A value too big for the fixed width is “escaped”: marked, and stored separately in full. Rare escapes keep the common case short.
fixed-length code
fixed-length code
Every value gets the same number of bits, n. Wasteful compared with an entropy coder, but any value’s position is known in advance, so decoding is trivially parallel and random access is free.
grid-aware table
grid-aware probability table
A probability table that describes the value, not the code number: a Laplace bump in value units, centred on the prediction, whose probability for each 8-bit code is the area over that code’s grid cell. Needed on E4M3, where a single bump in index space fits badly.
Huffman code
Huffman code
The best prefix code for known symbol probabilities, built by repeatedly merging the two rarest symbols. Codeword lengths are whole bits, close to each symbol’s surprisal.
index tax
index tax (the cost of naming a centroid)
The log2​C bits per vector that vector quantization spends to say which centroid was used. A codebook helps only if it saves more bits than this.
linear prediction
linear prediction across elements
Guessing an element’s value from elements already decoded in the same cherry, as a weighted sum; the table of which elements and which weights is stored once per punnet.
lossless
lossless compression
Compression after which the original is rebuilt exactly, bit for bit. The opposite, lossy compression, keeps only an approximation.
lossy
lossy compression
Compression that throws some detail away for good and rebuilds only an approximation (JPEG photos, 2-bit KV quantization). This project is lossless.
LZ matching
LZ matching (Lempel–Ziv)
The trick at the heart of zip and zstd: when a string of bytes has appeared before, write “copy n bytes from k bytes back” instead of the bytes themselves.
prediction
prediction and predictor
A guess x^ of the next value made only from things the receiver also knows. The rule that makes the guess is the predictor.
predictive coding
lossless predictive coding (DPCM)
Predict each value from what is already known, store the exact integer residual, entropy-code the residual. Lossless audio (FLAC), lossless images (PNG filters) and this project all have this shape.
product quantization
product quantization (PQ)
Split each vector into nsub​ pieces and give each piece its own small codebook. Much larger effective codebooks for the same storage; the same economics as plain VQ.
random access
random access
Being able to decode any single item on its own, without decoding what came before it. Stream compressors (zstd, arithmetic coding) give it up; fixed-length codes keep it. The leash is random access as a rule.
rANS
rANS (range asymmetric numeral systems)
A modern entropy coder with arithmetic coding’s near-ideal rates and much faster decoding. Like arithmetic coding, it keeps a running state, so a stream decodes front to back.
reference cherry
reference cherry
Another cherry of the same punnet, stored in the dictionary or already decodable, that a compressor uses as the prediction for a cherry; the delta then codes the exact difference. The sibling stage grown up.
reference tree
reference tree
The links from every cherry of a punnet to its reference cherry; the best compressors use the punnet’s minimum spanning tree by distance, so each cherry hangs off its closest relative, usually an echo.
residual
residual
The exact difference between a value and its prediction, r=x−x^. In lossless coding it is an integer and is stored exactly; good predictions give small residuals that cost few bits.
stage
stage (one node of a compressor's graph)
One step of a compressor’s dataflow graph: a bit-field split, a predictor (furrow statistics, a reference cherry, a linear prediction, a basis, a codebook), the exact residual, a quantiser on the dictionary side, an entropy coder or a fixed-length code, the layout. Part V is the catalogue.
trained dictionary
trained dictionary (zstd)
A zstd dictionary built from a sample of typical records and given to both sender and receiver in advance, so that even a single small record compresses as if the compressor had seen its siblings.
transform coding gain
transform coding gain
The bits saved per element by rotating data to its KLT axes before coding, 21​log2​(AM/GM) of the eigenvalues. Large only when a few directions hold most of the spread.
zstd
Zstandard (zstd)
A widely used general-purpose lossless compressor. It replaces repeated byte strings with short references to an earlier copy and entropy-codes the rest; it can be primed with a trained dictionary.

statistics

centroid
centroid
The average point of a group of vectors; the representative stored in a codebook.
covariance
covariance and correlation
How much two furrows move together. Correlation is covariance rescaled to −1 … +1. Correlated furrows can partly predict each other.
distribution
probability distribution
The list of all possible outcomes together with their probabilities. A histogram of real data is an estimate of it.
Gaussian
Gaussian (normal) distribution
The bell curve. Sums of many small independent effects look Gaussian. For a given spread it is the most unpredictable shape, so it is the honest worst case.
histogram
histogram
A count of how often each value (or range of values) occurs in a sample; the measured estimate of a distribution.
k-means
k-means clustering
The standard way to fit a codebook: alternately assign every vector to its nearest centroid and move each centroid to the average of its vectors, until nothing changes.
Laplace
Laplace distribution
A sharper, pointier cousin of the bell curve (two exponential tails) with scale β. Prediction residuals usually look like this, so compressors assume this shape for them.
mean
mean μ
The average value, μ. Subtracting it is the simplest prediction of all.
Monte Carlo
Monte Carlo simulation
Checking a claim by simulating many random samples on a computer and measuring, instead of (or as well as) deriving it with formulas.
paired difference
paired difference
One compressor’s score minus another’s on exactly the same punnets. The campaign computed it per sequence with its spread over sequences; the protocol of 2026-11-03 computes it per punnet with its Student-t confidence interval and quotes the per-sequence spread as the check.
R²
R² (fraction of variance explained)
The share of a value’s variance that a predictor accounts for, R2 between 0 and 1. The residual keeps variance (1−R2)σ2.
same-window comparison
same-window comparison
Two compressors or two cherry shapes run on exactly the same elements; the only fair way to rank cherry shapes.
standard deviation
standard deviation σ
The typical distance of a value from the mean, σ. Halving it saves one bit per value for bell-shaped data.
standardize
standardizing a furrow
Subtract a furrow’s mean and divide by its standard deviation, so every furrow has mean 0 and spread 1 and furrows measured in different units can be compared.
variance
variance σ²
The average squared distance from the mean, σ2: how spread out values are. Its square root σ is the standard deviation.

vectors & linear algebra

furrow
furrow (one element position followed along the token axis) · “the Furrow”
One fixed elem_id, read across many vectors: v[:, layer_id, head_id, elem_id] in the orchard, one sensor’s column in a table of readings. Per-furrow statistics are a location and a scale for each element position.
KLT
Karhunen–Loève transform (KLT) · “the Compass”
The rotation of the axes that lines them up with the directions in which the data spreads most (the same thing as PCA). After it, the coordinates are uncorrelated and can be coded one by one with no loss of efficiency.
AM/GM
arithmetic mean over geometric mean
The ratio of the ordinary average of the eigenvalues to their geometric average. It is 1 when all are equal and grows when a few dominate; 21​log2​ of it is the transform coding gain.
covariance matrix
covariance matrix
The d×d table of covariances between every pair of furrows. Its eigenvectors are the KLT axes and its eigenvalues the spreads along them.
eigenvalue
eigenvectors and eigenvalues
For a covariance matrix, the eigenvectors are the natural axes of the data cloud and the eigenvalue λ of each is the variance along it.
element
element (one stored number, and its position `elem_id`)
One number inside a vector, and its position elem_id from 0 to d−1. “Bits per element” counts bits per stored number. The same position across many vectors is a furrow.
lifting
lifting (integer-reversible transforms)
A way to split a rotation into a few integer “shear” steps, each exactly reversible, so a transform can be lossless on integers. Used in lossless JPEG 2000.
low rank
low rank
Data whose spread lives mostly in a few directions (a few large eigenvalues, the rest small). The sharper the drop, the more a KLT saves.
PCA
principal component analysis (PCA)
The statistics name for the KLT: rotate to the directions of greatest spread. Same mathematics, different tradition.
PLUS factorization
PLUS factorization (a rotation as integer-reversible steps)
Writing a matrix as a reordering of its rows (P) times three triangular factors (L, U, S) whose diagonals hold only ones when the matrix is a rotation. Each factor can be applied to integers with rounding and undone exactly: lifting for whole matrices.
rotation
rotation (change of basis)
Describing the same points with a different set of perpendicular axes. Nothing about the data changes; only which numbers we write down.
sparse coding
sparse coding (a vector as a few atoms of a large dictionary)
Describe a vector as a weighted sum of a few vectors (“atoms”) picked from a large, fixed dictionary, and store only which atoms and their weights. VQ is the special case of one atom with weight 1; a KLT uses every axis with a weight.
vector
vector
An ordered list of d numbers, e.g. one weather reading (temperature, humidity, …) or one cherry. Each number is an element.

number formats

BF16
bfloat16 (BF16)
A 16-bit floating-point format with 8 exponent bits and 7 mantissa bits: the usual working format of LLMs.
exponent
exponent and mantissa
In a floating-point number, the exponent picks the power of two (the “binade”) and the mantissa picks the position inside it. In the orchard the exponent is predictable and the low mantissa bits are close to noise.
floating point
floating point (sign, exponent, mantissa)
Numbers stored as sign × mantissa × 2^exponent. Spacing between neighbours grows with size, so relative precision is constant and the grid is logarithmic.
FP8
8-bit floating point (E4M3, E5M2)
8-bit floats. E4M3 has 4 exponent and 3 mantissa bits (values up to 448), E5M2 has 5 and 2. Where orchard storage is heading.
index space
index space (counting grid steps)
Number the representable values of a format in order, …, −1, 0, 1, …, and work with those integer indices. A residual of 1 then means “one grid step”, however big the step is.
INT8
INT8 with a scale (a uniform grid)
Store x as the nearest integer to x/scale, between −127 and 127. Representable values are evenly spaced, so differences behave as in ordinary arithmetic.
quantization
quantization (rounding to a grid)
Rounding numbers to the nearest point of a fixed grid of representable values. Done once, it defines the exact values our lossless compressor must reproduce.
scale group
scale group (numbers that share one rounding ruler)
The set of numbers that are rounded with one shared ruler, one smallest value and one step size. Per-furrow rounding makes each scale group one furrow over a run of tokens; per-token rounding makes it one token’s vector.

memory, caches & hardware

HiSparse
HiSparse (Xie et al., 2026) · “the Two-tier Library”
The serving system we build on. It keeps each sequence’s orchard in host memory and a small least-recently-used hot cache of raw picks per layer on the GPU. The LLM’s outputs are unchanged.
hot cache
hot cache (HiSparse's per-layer GPU buffer) · “the Hearth”
HiSparse’s small buffer of B raw picks per sequence per layer, kept in GPU memory and managed least-recently-used. Picks found there are hits; the rest are misses fetched from host memory over the link.
bandwidth
bandwidth and latency
Bandwidth is how many bytes per second a link carries once data flows; latency is how long one ask takes to start arriving. Many tiny scattered reads hurt both.
Bélády
Bélády's optimal policy
The clairvoyant eviction policy: evict the item whose next use is furthest in the future. Impossible in practice, but it bounds what any policy could achieve.
budget share
budget share φ (the share of the context one layer's picks cover)
φ=k/t: the positions one layer’s picks cover at step t, over the context so far (share = k * g / t when a pick is a squeezed row of g positions). The Pin: 2048 of 100 384, 2.0 %. On the Bachelor, miss rates at a given B/k follow φ, not k, so numbers move between LLMs at equal φ.
burst factor
burst factor (p99 over mean misses per layer per step)
The 99th percentile of one layer’s misses per decode step, divided by their mean. 2.9 on the Bachelor at the Pin’s budget share and B=2k (2.2 to 3.8 across layers): a link sized for the mean is late at one step in a hundred unless prefetching smooths the peaks.
cache
cache
A small, fast memory that keeps copies of some items from a big, slow one. An item found in it is a hit; otherwise a miss, and the item must be fetched. On this site the word stands alone only for real caches: the hot cache and the dictionary shelf. The orchard is not one.
data path
data path (where compressed orchard bytes travel, and how they are read)
Where a compressed orchard travels and how it is read back: a bulk transfer between machines, a network fetch of a stored prefix, the GPU-resident footprint, or the sparse-decode miss path of scattered single-cherry reads. The path, more than the statistics, decides what a compressor may look like.
disaggregated serving
disaggregated serving (prefill and decode on separate GPUs)
Running the prefill of a prompt and the decoding of its answer on different GPUs or machines. The finished orchard of the prompt must then be shipped from the prefill side to the decode side, in one bulk transfer per sequence.
eviction
eviction
Removing an item from a full cache to make room for a new one. The eviction policy decides which item goes.
half-gain rule
the half-gain rule (sequences per GPU grow as about 1/√ρ for a code with no bytes per sequence)
For a code that keeps no bytes per sequence on the GPU and shrinks every miss to a share ρ of a pick, the best hot-cache size balances the link against GPU memory, and sequences per GPU grow as ρ−1/(1+α)≈1/ρ​, not as 1/ρ: about half of the gain goes into a smaller hot cache. At the Pin, solo’s 0.804 gives 141 sequences per GPU against 127, and the floor of 0.57 gives 166.
HBM
HBM (GPU memory)
High-bandwidth memory stacked next to the GPU: very fast, small (tens of GB) and expensive. The hot cache lives here.
hit / miss
hit and miss
A hit is an ask served from the cache; a miss must fetch the item from slower memory. The miss rate m is the fraction of asks that miss.
host DRAM
host memory (DRAM)
The CPU’s main memory, much larger than HBM and much slower to reach from the GPU. HiSparse keeps every orchard here.
LRU
least recently used (LRU)
The eviction policy that throws out the item whose last use was longest ago. Simple, and very good when recent use predicts future use.
miss-rate curve
miss-rate curve m(B)
The miss rate of an LRU cache as a function of its size B. One curve, read off the reuse distances, gives the miss rate at every size.
PCIe
PCIe link
The wire between host memory and the GPU. PCIe Gen5 ×16 carries about 64 GB/s each way (≈50 in practice), roughly 100× less than HBM.
popularity
stretch popularity
The running count of misses (or picks) a stretch has received over a window of recent decode steps; the statistic that decides which stretches are on fire.
reuse distance
reuse distance (stack distance)
For an ask, the number of distinct other items asked for since this item’s previous ask. Under LRU with B slots, an ask misses exactly when its reuse distance is at least B.
slot price
slot price (the link bytes one more hot-cache slot saves)
With misses falling as m∝B−α, one more hot-cache slot per layer removes about αmk/B misses per decode step, αmke/B link bytes. A dictionary on the GPU holds the memory of w slots, so it helps only if it saves more link bytes than w slots would. Not the exchange rate of Part II (variance explained to bits).
the link
the link (host memory ↔ GPU)
The PCIe wire between the host memory that holds the orchards and the GPU; Wlink​ is its practical bandwidth. Every miss and every dictionary load crosses it. The wire a textbook compression problem puts between its sender and its receiver.
tokens per second
decode throughput per GPU
Output tokens one GPU produces per second across all its concurrent sequences: the sequences it serves divided by the time per output token, TPS=N/TPOT. About 3,630 for HiSparse on the Pin.
trace replay
trace replay (re-running caches on recorded picks)
Recording which picks a (stand-in) indexer names at every decode step, then re-running the hot cache and the dictionary shelf on that list. It measures miss rates, the δ-miss fraction and dictionary loads without running any kernel.

transformers & attention

indexer
indexer (the selector of sparse attention) · “the Scout”
A cheap scorer that, at every layer and every decode step, looks over all past positions and names the k picks attention will read. Its picks are announced before any bytes of the orchard are touched.
orchard
the orchard (all keys and values one sequence has grown) · “the Orchard”
Every key and every value of one sequence at every KV layer, kept in host memory: two arrays k, v of shape (n_tokens, n_kv_layers, n_kv_heads, head_dim). It grows one row per token and is never pruned. A store, not a cache, whatever its usual name suggests.
pick
pick (one unit of demand, as the indexer names it) · “the Pick”
One (layer_id, token_pos_id) the indexer selects at one decode step: the unit the hot cache holds and a miss fetches. What a pick covers depends on the LLM (one layer in DSA, a group of layers in GLM-5.1). A pick is served with one or more cherries.
attention
attention (query, key, value)
The step where a token looks back. Its query vector is compared with every stored key; the scores become weights; the output is the weighted mix of the stored values.
DSA
DeepSeek Sparse Attention (DSA)
The top-k sparse attention of DeepSeek-V3.2 (also used by GLM-5.x), with a small trained “lightning indexer” that scores every past token cheaply.
hidden state
hidden state
The vector x a transformer carries for each token between layers; keys, values and queries are fixed linear projections of it.
KV head
KV head and GQA
Attention is split into several heads that work in parallel. With grouped-query attention (GQA) several query heads share one key/value head, head_id; only the KV heads are stored, which shrinks the orchard.
KV layer
KV layer (a layer that keeps keys and values)
A layer that keeps keys and values for every token. In hybrid LLMs only some layers do: 6 of Qwen3.5-2B’s 24; the others carry a fixed-size state and have nothing per token to store. The orchard’s layer_id counts KV layers only.
layer
layer
One of the stacked processing stages of a transformer, numbered by layer_id. Each layer has its own attention and, if it is a KV layer, its own rows of the orchard.
LLM
the LLM (always named)
The language model whose orchard we study, always named: GLM-5.1 on the Pin, Qwen3.5-2B on the Bench. A stand-in LLM is one measured in place of the real target. Never the bare word.
MLA
multi-head latent attention (MLA)
DeepSeek’s variant of attention that stores one compressed latent vector per token per layer instead of separate keys and values. Still one fixed-size row of the orchard per token per layer.
prefill / decode
prefill and decode
Prefill reads the whole prompt at once; decode then generates the answer one token per step, each step reading everything stored so far.
query
query
The vector q the current token uses to score every stored key at one layer; one per query head. Queries are not stored, which is why the dataset has none unless they are recomputed.
RoPE
rotary position embedding (RoPE)
The way many LLMs tell attention where a token sits: by rotating pairs of key and query elements by an angle that grows with the position. Keys are more regular before this rotation than after it.
sequence
sequence (one LLM context)
One conversation’s tokens as the LLM sees them, from its first token to now; the thing that grows an orchard. A serving system runs many sequences at once. On this site the word never means “the order of cherries”.
sparse attention
top-k sparse attention
Attention that reads only k picks per layer per step (named by an indexer) instead of every stored token. Compute stops growing with context; storage does not.
stand-in LLM
stand-in LLM (a small open LLM measured in place of the target)
A small open LLM whose orchard is measured in place of the real sparse-attention target: Qwen3.5-2B on the Bench. Whether its statistics transfer to GLM-5.1 is itself a risk.
the Bachelor
the Bachelor (a dump of Qwen 2.5 1.5B with queries, where the pick traces were computed)
Five coding-agent sequences of 24 507 to 30 075 tokens run through Qwen 2.5 1.5B Instruct, with keys, values and queries of all 28 layers kept (keys and queries after RoPE). The stand-in indexer and the hot-cache replay of Part XI ran on it. A stand-in LLM’s dataset, not a third reference setting: its numbers reach the Pin only through the scaling rules of Part XI.
token
token
The unit of text an LLM reads and writes: a word or a piece of one. Its position in the sequence is token_pos_id. An LLM generates one token per decode step.
TPOT
time per output token (TPOT)
How long one decode step takes for a sequence: 30 ms on the Pin. Every byte moved per step must fit into this time.

this project's own words

cat-sequence ladder
the cat-sequence ladder (the intuitive argument) · “the Ladder”
The intuitive argument for the project: a cherry is less surprising against its own sequence than against everything, and least surprising against its own neighbourhood. Right in direction, leaky in its evidence, and harsh in its exchange rate.
cherry
cherry (one unit of ask-and-answer) · “the Cherry”
The unit the receiver asks for and the sender answers with one delta: the chosen vectors of one token position of the slice, written as an index expression with its element count, e.g. cherry(t) = v[t, l, :, :], 512 elements, cherry_bytes == 512. Every cherry of a scenario has the same size, known to both sides in advance; cherries that stack several positions are out of scope.
compressibility curve
the delta–dictionary compressibility curve · “the Arch”
For one compressor on one scenario, the points (delta share, dictionary share) of its configurations. What is read off it is the point of lowest MDL ratio and the split it falls at; the lowest ratio over all compressors is the roofline.
delta
delta δ (what is sent for one cherry once the dictionary is known) · “the Remainder”
The bytes sent for one cherry; with the dictionary they rebuild it bit for bit. Its size over the cherry’s raw size is the delta share, ρ.
dictionary
dictionary (side information shared by a punnet) · “the Almanac”
Bytes shared by many cherries and held by the receiver before it asks for any of them, so that each cherry can be sent as a short delta. A zstd trained dictionary, a codebook, furrow statistics and a set of reference cherries are all dictionaries. Not a Python dict.
dictionary shelf
dictionary shelf (kvblockdiff's resident dictionaries) · “the Bookshelf”
kvblockdiff’s per-layer set of nD​ punnet dictionaries kept in GPU memory, one per stretch that is on fire. A miss in a stretch whose dictionary is on the shelf can be served by a delta.
echo similarity
echo similarity (repeats of the same token) · “the Echo”
An earlier occurrence of the same token, however far away, predicts a cherry far better than its neighbours do. Reference trees live on echoes; in the data the axis that mattered was repetition, not distance.
fallen-apple similarity
fallen-apple similarity (token axis) · “the Apple”
Hypothesis: a cherry is cheaper to store exactly given a cherry of the same layer a small token distance Δ away, and the closer the neighbour the cheaper. A curve over Δ, not a threshold. Measured: weak, except in the middle layers.
furrow statistics
furrow statistics (the loc stage) · “the Anchor”
The lightest dictionary: for each furrow, a typical value (location) and a spread (scale). Predict each element by its furrow’s location; store the exact difference. Weighs about two cherries, no per-cherry tax.
global scope
global scope (one dictionary for all sequences) · “the Globe”
A dictionary fit once, offline, on a calibration corpus and shared by every sequence. Free at serving time; captures only what all texts have in common.
heavy stretch
heavy stretch · “the Anvil”
A stretch that holds many of the current step’s picks. If picks pile into a few heavy stretches for many steps, keeping their dictionaries on the shelf is cheap.
kvblockdiff
kvblockdiff (this project's proposal) · “the Delta Store”
Serve the indexer’s picks as deltas against punnet dictionaries kept on the GPU, so that a hot-cache miss moves a delta instead of a raw pick and the GPU rebuilds it bit for bit. One spelling, no hyphen.
leash
the leash (the cap on dictionary bytes one cold decode may touch) · “the Leash”
Rebuilding any one cherry from cold may read at most leash × cherry_bytes distinct bytes of the dictionary, counted in the scenario’s own cherry and checked for every cherry. One leash per stretch length: 137 at 512 positions, 293 at 4096, 1103 at 16 384, 14 503 for the whole sequence. It keeps “compress the whole punnet as one stream” out of the game.
Lucky Louis property
the Lucky Louis property of the indexer · “the Gambler”
From one decode step to the next, the indexer re-picks mostly the same positions, so a cache that bets on last round’s winners keeps winning. It is about WHICH picks are wanted, not about their bytes.
neighbour similarity
neighbour similarity (umbrella term) · “the Neighbours”
The family of hypotheses that a cherry costs fewer bits to store exactly when a neighbouring cherry along some axis of the orchard is already known. Members: fallen-apple (token axis), upstairs (layer axis), stereo (head axis), echo (repeats).
punnet
punnet (all the cherries one dictionary serves) · “the Punnet”
All cherries of one stretch under one slice and one cherry shape: what one compress call sees and what one dictionary serves. punnet_size cherries. Not an orchard and not a stretch.
raw miss
raw miss (a miss served by the raw pick) · “the Crate”
A hot-cache miss whose stretch’s dictionary is not on the shelf, so the full raw pick (e bytes) crosses the link, exactly as in HiSparse today.
sequence scope
sequence scope (one dictionary per sequence) · “the Spool”
A dictionary fit on one sequence’s own slice, loaded once when the sequence is admitted. Captures what is special about this conversation. The same as stretch scope with one stretch as long as the sequence.
sibling
sibling prediction (the sib stage) · “the Twin”
Use another cherry of the same punnet (the nearest “sibling”) as the prediction, plus a pointer to it. Cheap side information, but the residual is the difference of two noisy vectors, so its noise doubles. The reference tree is its grown-up form.
slice
slice (which coordinates of the orchard are in play) · “the Slice”
The rule naming which part of the orchard a scenario compresses: keys or values or both, which layers, which heads, which elements; written as the Python slice it is, e.g. v[:, [1, 3], 0, :].
solo
solo (compressors with an empty dictionary) · “the Hermit”
Coding each cherry by itself with one fixed, context-free table (per-furrow histograms fit once on a calibration corpus). 0.778 on the Bench’s values. The baseline every dictionary must beat.
stereo similarity
stereo similarity (head axis) · “the Stereo Pair”
The two KV heads of a layer at one token are two views of one vector: their elements have a cosine near zero, yet joining them into one cherry saves about 0.85 bit per element. The strongest structure the campaigns measured.
stretch
stretch (a run of consecutive token positions) · “the Stretch”
stretch_len consecutive token positions of one sequence; stretch_id = token_pos_id // stretch_len. A knob we choose, not a fact of the data, and it says nothing about which tensor coordinates are in play.
stretch scope
stretch scope (one dictionary per punnet) · “the Brick”
A dictionary per punnet, fit on the punnet itself. Fits the local neighbourhood best, but there are many of them per sequence and the ones in use must be on the GPU.
the Bench
the Bench (the campaigns' data-side reference setting) · “the Bench”
The second frozen rig: Qwen3.5-2B’s six KV layers, 2 heads × 256, 512-byte cherries for one token’s values at one layer, 225K-token coding-agent transcripts, FP8, on one RTX 5080 with a 50 GB/s link. No indexer ran on it, so picks, misses and step time are not measured there.
the Pin
the Pin (the deployment-side reference setting) · “the Pin”
One of the two frozen rigs every estimate is quoted for: HiSparse’s GLM-5.1 deployment at 8-bit storage: 78 sparse layers, 2048 picks per layer per step, 100K-token context, 640-byte cherries, 30 ms per token, a 50 GB/s link, 30 GB of GPU memory for orchards.
upstairs similarity
upstairs similarity (layer axis) · “the Staircase”
Hypothesis: the cherry of the same token one layer up is partly predictable from the one below it. Measured: small, and by kind of layer rather than by adjacency.
victim tier
victim tier (a GPU tier of evicted picks' deltas) · “the Lifebuoy”
A second GPU tier holding the deltas of picks just evicted from the hot cache. If one of them is picked again it is rebuilt on the GPU instead of being fetched over the link.
δ-miss
δ-miss (a miss served by a delta) · “the Feather”
A hot-cache miss whose stretch’s dictionary is on the shelf, so only the delta (ρe bytes) crosses the link and the GPU rebuilds the pick.
big-picture question
big-picture question (Q1–Q3)
An open-ended question the project exists to get closer to: Q1 (what structure does the orchard have, in bits?), Q2 (can a dictionary-and-delta store beat raw storage on the miss path?), Q3 (do picks pile into few stretches?). Too wide to answer with one experiment.
bits per element
bits per element (bpe)
The rate of a lossless compressor per 8-bit element, everything included (residuals, per-cherry tax, the dictionary spread over its punnet). Raw storage is 8; bits per element = 8 × MDL ratio.
calibration corpus
calibration corpus (data kept apart for the global scope)
The data a shared table or a solo table is fitted on: the dev sequences, or a separate training corpus, never a holdout sequence. A table fitted on a holdout sequence is a hidden dictionary.
campaign
research campaign
One run of the autonomous research loop: several AI researcher agents writing and testing compressors against one harness, under one set of rules, with every trial recorded. C1 was the night of 29–30 October 2026; C2 the day of 30 October.
cherry shape
cherry shape (how the slice is diced into cherries)
The dicing rule of a scenario, written as the index expression of one position’s cherry with its element count: v[t, l, h, :] makes one cherry per head vector (256 elements), v[t, l, :, :] one per token at one layer (512), v[t, :, :, :] one per token across six layers (3072). Never a bare shape tuple. The other half, with the slice, of what the campaigns called a split.
cold decode
cold decode
Rebuilding one cherry from nothing but its own delta, the dictionary and the scenario’s known constants, without having decoded any other cherry first. The way the harness checks every cherry and counts its reads.
cost per million tokens
cost per million output tokens
The price of one GPU-hour divided by the tokens that hour produces, scaled to a million. The price is an assumption; the ratio between two designs is not.
decision rule
decision rule
The table, written before any data, that maps an experiment’s readings to what happens next.
dictionary scope
dictionary scope
What a dictionary is fit on and shared by: global (all sequences), sequence (one conversation) or stretch (one punnet). The axis that decides how the dictionary’s bytes enter the score: in full per punnet, in full to the one punnet a whole sequence is, or not at all (a shared table).
dictionary weight
dictionary weight w
A dictionary’s size measured in cherries’ worth, w, so it is ∣D∣=we bytes. Spread over a punnet of b cherries it costs 8w/b bits per element.
entropy rate
entropy rate (the scientific number)
The rate an ideal entropy coder would reach on the residuals, plus the per-cherry tax and the amortized dictionary. What arithmetic coding or rANS would achieve.
experiment question
experiment question (one scenario, one decision)
A question asked together with its scenario, its controls and each possible outcome’s meaning, all written down before any data.
fixed-length rate
fixed-length rate (the engineering number)
The rate of a fixed-length code with escapes on the residuals, plus the per-cherry tax and the amortized dictionary. What a fast GPU decoder achieves, and directly the delta size on the link.
harness
the harness (the referee)
The program every compressor runs through: it checks the contract for every cherry in a fresh process, counts every byte by one rule, measures reads against the leash, pairs scores on the same punnets and records every trial in a ledger no one may edit.
lever
the two levers (cheaper misses, cheaper slots)
Lever 1 makes misses cheaper (move ρe instead of e over the link); lever 2 makes hot-cache slots cheaper (keep heavy stretches as deltas in GPU memory).
on fire
an on-fire stretch
A stretch whose popularity crossed the threshold, so its dictionary has been loaded onto the shelf and its misses travel as deltas; the opposite state is ice.
per-cherry tax
per-cherry tax (side information sent with every cherry)
Bits a stage must put into every delta on top of its residual: which centroid (log2​C bits), which reference cherry (log2​b bits), a flag. Spread over the cherry’s d elements it is the tax of the bill.
reads
reads (dictionary bytes one cold decode touched)
The distinct dictionary bytes the decoder touched while rebuilding one cherry from cold, in cherries’ worth; re-reads count once and the cherry’s own delta is free. Must stay under the leash for every cherry, not on average.
reference setting
reference setting (a frozen rig every number is quoted for)
One fixed set of numbers (an LLM, its shapes, a machine, what was measured on it) that every estimate on the site is quoted for, so that pages can be compared. There are two: the Pin (GLM-5.1 on 8 × H200, the deployment side) and the Bench (Qwen3.5-2B on one RTX 5080, the data side). The pill in the top bar switches between them.
roofline
roofline (of the compressibility curve)
The lowest MDL ratio reached on a scenario by any compressor at any configuration, with its confidence interval. Not a lower envelope over the two shares: the shares are not scores, only their sum is.
scenario
scenario (one fully specified compression problem)
The tuple (slice, cherry_shape, stretch_len, leash, fmt, llm, corpus). Written in prose as V of one token, v[t, :, :, :] · stretch 4096 · leash 293 · fp8 · target 02. Twelve are in scope: three cherry shapes of one position crossed with four stretch-and-leash pairs. Two scenarios with the same slice and different cherry shapes are different problems.
screen
screen
A fixed, cheap test: a tenth of the stretches of two (or five) sequences at one scenario. Two screens read different punnets, so their scores cannot be subtracted.
sender / receiver
sender and receiver
The two ends of the scenario: the sender holds the orchard in host memory and prepares dictionaries and deltas at leisure; the receiver on the GPU side asks for one cherry at a time and must rebuild it from its delta and the dictionary it already holds.
shared table
shared table
Any data structure specific to the LLM and the scenario but to no sequence, of any size, held by both sides before any sequence is seen and never charged: side information. Fitted on dev sequences or on a separate training corpus, never on a holdout sequence. Allowed by the human’s ruling, deferred to a later step, used by no compressor yet.
shelf coverage
shelf coverage (the share of the context the dictionary shelf spans)
n_D * stretch_len / t: how many positions the stretches on the dictionary shelf hold, over the context so far. If misses landed evenly, the δ-miss fraction would equal the coverage; the shuffled twin of a trace measures exactly that value.
shuffle control
shuffle control
Rerun the measurement after shuffling tokens across sequences. Any gain that depends on neighbours being neighbours must vanish; a gain that survives is a bug.
the bill
the bill (rate = residual bits + per-cherry tax + dictionary share)
Every compressor’s rate in bits per element has three lines: what the residuals cost, what each cherry carries besides its residual, and the dictionary’s bytes spread over its punnet (8w/b). The harness charges all three, always.
the contract
the contract (what makes a compression valid)
deltas, dictionary = compress(punnet) once on the sender’s side; then decompress(deltas[i], dictionary) == punnet[i] for every cherry i, bit for bit, decoded cold. Anything less is not a result.
the interesting range
the interesting range of dictionaries
Dictionaries large enough to carry a punnet’s shared structure and too large to keep resident for every stretch: kept in host memory, brought to the GPU for the stretches the indexer keeps wanting.
the leak
the leak (hit rate is about queries, not bytes)
The flaw in the intuitive argument: HiSparse’s high hit rates follow from slowly drifting queries and say nothing about whether the picks’ bytes are alike. A Monte Carlo with i.i.d. keys reproduces the hit rates with zero compressibility.
the trap
the trap (the exchange rate is harsh)
Explaining 75 % of a value’s variance saves only one bit of eight; 94 % saves two. A lossless compressor is paid in variance explained at a harsh rate, and the noise floor is paid in full.
verified
verified result
A score whose every cherry was rebuilt bit for bit by a separate decoder-only process from the stored bytes alone, with its reads counted. Anything else is a quick trial, a code-length estimate or a bound.
δ-miss fraction
δ-miss fraction f_D
fD​, the share of misses that are δ-misses (their stretch’s dictionary was on the shelf). Decided by the residency policy and by where misses land.
