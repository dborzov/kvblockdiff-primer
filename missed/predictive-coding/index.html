VII.9

The real home of the problem: predictive coding with side information

The first draft looked for relatives among lossy KV papers and general-purpose compressors. The family that has solved this exact shape for seventy years is lossless predictive coding — and its theory of side information says, in one line, what a δ-miss is.

When a problem is new to you, the first job is to find out who solved it before, under another name. The first draft of this proposal looked in two neighbourhoods. One was the papers that shrink KV caches by quantizing them (lossy: they throw bits away, Part V). The other was general-purpose compressors like zstd, built for long streams of text.

Both are neighbours. Neither is home.

Back storyWhat the first draft did not use

It described kv-blockdiff as a new kind of dictionary compression. It never named the field that has done exactly this since the early 1950s: lossless predictive coding, and the information theory of side information behind it. Item 8 of the old “What Dima missed” list: the home of this problem is not KV quantization and not LZ.

Same shape, older names

Record a steady musical note at 16 bits per sample. Neighbouring samples are nearly equal, so a coder can guess each sample from the ones before and store only the miss. That is predictive coding, the shape Part II taught on the Gull Rock thermometer. Write xi​ for sample number i. The FLAC audio format offers four fixed guesses x^i​:

  • order 0: guess 0 — store the sample itself;
  • order 1: guess “the same as last time”, xi−1​;
  • order 2: guess “continue the straight line”, 2xi−1​−xi−2​;
  • order 3: guess “continue the parabola”, 3xi−1​−3xi−2​+xi−3​.

The residual is then written with a Rice code: a few fixed bits plus a short unary tail, a close cousin of a fixed-length code with an escape. Try all four on a synthetic recording.

☞ Things to try
  1. At the default noise (σ = 4) the order-3 guess wins: 6.3 bits per sample instead of 16, and order 0 needs 13.4.
  2. Raise the noise to 10. Now order 2 wins (7.1 bits) and order 3 falls behind (7.7): it multiplies the noise variance by 20.
  3. Push it to about 100: order 1 overtakes order 2. The more past samples a guess combines, the more of their noise it drags in.

Points 2 and 3 are worth a second look. A residual is a difference, and the variances of independent noises add. Order 1 doubles the noise variance; order 2 multiplies it by 6; order 3 by 20. This is exactly why the sib dictionary, which predicts an entry from a noisy sibling, starts with doubled noise (VI.8 sib: the Twin).

Now line up the family.

codec predicts each value from stores codes the residual with
FLAC (audio) the previous 1–4 samples, or a fitted filter of up to 32 exact integer residual Rice codes
PNG (images) the left or upper pixel, their average, or the “Paeth” pick among three neighbours — chosen per row exact residual DEFLATE
JPEG-LS (images) a median of three candidates built from neighbours, then a per-context bias correction exact residual Golomb codes, one per context
lossless JPEG 2000 an integer wavelet built from lifting steps exact coefficients arithmetic coding
kv-blockdiff the block’s dictionary (location, basis, centroid or sibling) exact residual in 8-bit code space fixed-length codes with escapes

Notice anything? The bottom row is not a new species. Only the thing predicted from is new: a dictionary fitted to a block, where the others use neighbouring samples or pixels.

Takeaway
  • kv-blockdiff has the exact shape of lossless audio and image coders: predict, store an exact integer residual, code it simply.
  • Predictors that subtract noisy neighbours multiply the noise — order 1 by 2, order 2 by 6. The sib dictionary inherits the same penalty.

Side information, said precisely

ReminderConditional entropy and mutual information

H(X∣Y) is the average number of bits needed to describe X when the receiver already knows Y — the season almanac of II.5 Side information. It is never larger than H(X), and the difference is the mutual information I(X;Y) (II.6 Mutual information).

The theory behind the table above is one line long.

bits per item when both ends know YH(X∣Y)​​=bits aloneH(X)​​−what Y already saysI(X;Y)​​(VII.9·1)
SymbolsWhat’s in this equation (4)
H
entropy [bits] — Average surprisal: the fewest bits per symbol any lossless code can average. II.4
X
a message / random variable — The thing being described or sent (tomorrow’s weather, one value, one entry). II.4
Y
side information — Something the receiver already knows (the season, a dictionary). II.5
I
mutual information [bits] — Bits saved by knowing one thing when describing another: I(X;Y)=H(X)−H(X∣Y). II.6

For us, X is an entry and Y its block’s dictionary Dj​. A δ-miss is this equation in hardware. The link carries about H(X∣Y) bits per element because the GPU already holds Y.

Information theory also has a second, stranger version of the story.

Who holds the side information?
At both ends
  • The encoder sees Y, subtracts its prediction, and sends the residual.
  • Rate: H(X∣Y).
  • Examples: DPCM, FLAC, a zstd trained dictionary, kv-blockdiff (the block is in hand when it is encoded offline).
At the decoder only
  • The encoder never sees Y. It sends a short “hash” saying which bin X fell into; the decoder picks the bin member that fits its Y.
  • Slepian and Wolf (1973) proved the rate is still H(X∣Y) for lossless coding, given long enough blocks. Wyner and Ziv (1976) did the lossy version: for Gaussian data with squared error, nothing is lost at all.
  • Decoding is a search, not a subtraction.

We are in the easy column. The second column would matter only if the decoder’s side information were unknown at encode time. One example would be "decode against whichever sibling happens to sit in the hot cache". Our read: such a code must be sized for the least helpful neighbour it might meet. Practical versions also need long codewords and iterative decoding, which is far from a gather and an add. It is a curiosity to park, not a tool for wave 1.

Running themeSide information at both ends

Here the theme is at its most literal. The δ-miss costs H(X∣Y) only because the dictionary is on the GPU, and “the receiver must really have it” is the whole residency question of IV.4 kv-blockdiff, step by step.

Also on I.4 · II.1 · II.5 · II.25 · IV.1 · IV.4 · V.13 · VI.8 · VI.13 · VI.17
Takeaway
  • A δ-miss is conditional coding with side information at both ends; its ideal rate is H(E∣D).
  • Slepian–Wolf shows the decoder alone can hold the side information — elegant, but not needed here, and not GPU-friendly.

What changes in the plan

Knowing the family’s name turns open questions into look-ups.

  1. Residual codes. Rice and Golomb codes are the audio and image world’s fixed-length-with-escapes, with parameters chosen per partition or context, like our per-block widths (VI.10 Two rates for everything).
  2. Using a prediction without subtracting it. JPEG-LS chooses its code by context. On a logarithmic grid that is the safe way to use a prediction (VII.11 Context modelling never loses).
  3. Lossless rotations. Lossless JPEG 2000 rotates integers exactly with lifting (VII.10 Lifting: how a rotation becomes lossless).
  4. Bounds. Transform coding gain and rate–distortion bounds say what a predictor can win before anyone writes it (VII.13 Bounds before building).
  5. A warning. Any predictor built from noisy neighbours pays for their noise.

The measuring harness of Part IX (IX.1 The harness: one interface) is, in this light, a predictive-coding test bench, and the literature to mine includes lossless audio and image coding. What the family cannot supply is how much the KV statistics actually let a dictionary predict.

  • Only the KV statistics are new — and those are what wave 1 measures.
