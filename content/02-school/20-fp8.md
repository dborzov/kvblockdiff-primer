The 8-bit float on the Gull Rock chip (II.19) is not a toy. It is one of the two 8-bit floating-point formats that graphics processors now compute with, and storage of model numbers is heading towards it. This page gives it its name, then shows a way of looking at it that every later page relies on: as a ladder of numbered rungs.

## Two eight-bit floats {#fp8}

::: define fp8
- **What it is:** a floating-point number in 8 bits. Two layouts are common:
  - **E4M3:** 1 sign bit, 4 exponent bits, 3 mantissa bits. Values up to ±448; every value from about 0.016 to 448 within 6.25 % of a grid point; tiny "subnormal" values down to $2^{-9} \approx 0.002$.
  - **E5M2:** 1 sign bit, 5 exponent bits, 2 mantissa bits. A wider range (up to 57,344) and a coarser grid (within 12.5 %).
- **Example:** in E4M3, 12 is stored as `0 1010 100`: sign 0, exponent pattern 1010 (the binade [8, 16)), mantissa 100 (the fifth of eight steps: 8, 9, 10, 11, **12**, …).
- **Counting values:** E4M3 has 127 non-negative values (zero, 7 subnormals, then 15 binades of 8 values, minus one pattern reserved for "not a number"), so 253 distinct values with the negatives. On this site, FP8 means E4M3 unless we say otherwise.
:::

| format | bits | representable values | largest value | precision |
|---|---|---|---|---|
| INT8 with a scale | 8 | 255, evenly spaced | 127 × scale | half a scale step, everywhere |
| FP8 E4M3 | 1 + 4 + 3 | 253, logarithmic | 448 | within 6.25 % |
| FP8 E5M2 | 1 + 5 + 2 | about 250, logarithmic | 57,344 | within 12.5 % |

Turning a reading into one of these codes means rounding it to the nearest grid point.

::: define quantization
- **What it is:** rounding numbers to the nearest point of a fixed grid of representable values.
- **Example:** with E4M3, 11.4 °C becomes 11, and 0.1 becomes 0.1015625.
- **On this site** quantization has happened *before* our story starts. The rounded 8-bit values are the originals; a [[lossless]] coder must give back exactly these values, bit for bit. To fit a channel's range onto the grid, values are first multiplied by a scale; a power of two is chosen, because multiplying by a power of two is exact.
- **Easy to confuse with:** compression. Quantization throws information away once; everything afterwards on this site is lossless.
:::

::: takeaway
- FP8 E4M3: 1 sign, 4 exponent, 3 mantissa bits; 253 values up to ±448, logarithmically spaced. E5M2 trades precision for range.
- Quantization is rounding to the grid. It happens once; our coder must reproduce its result exactly.
:::

## Counting grid steps: index space {#index-space}

Here is the move that makes residuals easy. List all 253 values of E4M3 in increasing order and number them: zero gets index 0, the next value up gets 1, and so on to 448, which gets 126. Negative values get negative indices. Every FP8 code now corresponds to a whole number between −126 and 126.

::: define index-space
- **What it is:** working with the position of a value in the ordered list of representable values (its *index*), instead of with the value itself.
- **Example (E4M3):** 0 → 0, 0.1015625 → 29, 1 → 56, 2 → 64, 11 → 83, 12 → 84, 448 → 126.
- **A residual in index space** is a difference of indices: "how many rungs apart", however far apart the rungs are in value. It is always a whole number, so it can be coded exactly.
- **Easy to confuse with:** the bit pattern read as an integer. For E4M3's positive values the two agree; for negative values they do not.
:::

Index space is honest about the grid, and the grid is logarithmic. Play with it.

::: try
1. *12 vs 11*: one rung apart. Near 12 the E4M3 grid has a value every 1.0.
2. *0.1 vs −0.1*: the values differ by only 0.2, yet they are **58** rungs apart. Between them lie zero, all seven subnormals on each side and several whole binades.
3. *200 vs 100*: 8 rungs. Every doubling is 8 rungs, anywhere on the line (above the subnormals): 0.5 → 1 is also 8.
4. Keep the gap between the handles fixed and slide both: the E4M3 step count changes with position, the INT8 count does not.
:::

Count the codes and the picture is plain: **111 of the 253 values lie between −1 and 1**, and 57 between −0.1 and 0.1. A logarithmic grid spends as many codes on each binade below 1 as on each binade above it, so codes pile up around zero.

That has a consequence for prediction. Suppose a channel's values hover around zero, and a prediction is close in *value* but lands on the other side of zero, or a few binades lower. In index space the residual is large, and a large residual costs many bits. On an even INT8 grid the same prediction leaves a residual proportional to the value difference, wherever it sits.

::: theme grid-matters
The same prediction, with the same error in value, can leave a residual of 1 step or of 58 steps depending on where it falls on a logarithmic grid. An even grid treats every place alike. Which grid the numbers are stored on decides whether predict-then-correct pays off; Part VI measures how much ([[#homework-the-grid]]).
:::

::: note connection Why counting rungs is still the right idea
Index space makes every residual a whole number and keeps the code exactly reversible: the receiver adds the residual to the prediction's index and reads off the value. It is the natural home for lossless coding of FP8. The catch is only that "close in value" and "close in index" are different things near zero. Part IX fixes the exact recipe ([[#plan-fp8-target]]).
:::

::: takeaway
- Index space numbers the representable values in order; a residual is a count of rungs, always a whole number.
- On E4M3 a doubling is always 8 rungs, but near zero rungs are packed tight: 0.1 and −0.1 are 58 rungs apart.
- On an even grid, step counts do not depend on position. The grid decides how well prediction works.
:::
