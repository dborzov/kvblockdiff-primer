Here is a number that takes the wind out of Q2 as it is phrased. SplitZip, a lossless coder for KV caches, already makes 8-bit KV 1.14× smaller than raw storage, with no dictionary at all ([[#papers-splitzip]]). A global, context-free code per [[channel]] — [[solo]] coding — is worth about 1.1–1.3×. So "can a dictionary store beat raw storage?" has a boring answer: yes, and so can a store without dictionaries.

The real question hides behind the word *raw*.

## The question, in one sentence {#question}

::: note key Q2 in one line
Given the real access pattern — scattered single entries, random access, decoded at gather speed — which coder reaches the best trade-off between dictionary cost and delta size, and does its saving over solo coding survive the engineering constraints: fixed-length deltas, GPU decoding, the 8-bit grid?
:::

:::: compare Two bars a dictionary could aim at
::: col Beat raw
- The bar: 8 bits per element ($\vrho = 1$), HiSparse today.
- Solo coding passes it with no dictionary: $\vrho \approx 0.78$ with an ideal coder, $\approx 0.88$ fixed-length.
- Passing it says nothing about dictionaries.
:::
::: col Beat solo
- The bar: ≈ 6.2 bits per element (ideal) or ≈ 7 (fixed-length).
- Only *conditional* structure can pass it — what neighbours, requests or blocks share.
- This is Q2.
:::
::::

On the miss path a dictionary coder must clear four hurdles, and each one costs bits.

1. **The solo bar.** Every gain is counted from solo coding, not from raw.
2. **The dictionary's own cost.** A dictionary of [[weight]] $\vw$ shared by a block of $\vb$ entries costs $8\vw/\vb$ bits per element ([[amortization]]).
3. **The form factor.** Each entry must decode alone, given only its block's dictionary ([[random-access]]), with a fixed delta length per block, and at more than ~50 GB/s per GPU ([[#homework-break-even]]). A fixed-length code costs about 10–15 % more than an ideal one ([[#homework-two-rates]]).
4. **The grid.** On the logarithmic E4M3 grid, a prediction subtracted in grid steps loses badly when it explains less than ~70 % of the variance, and stays about 0.8 bit behind the same prediction on a uniform INT8 grid when it explains more ([[#homework-the-grid]]).

The figure lets you play with the first three. The bars are bits per element; the solo bar is the one to clear.

::: figure fig-questions-bar qBar
**The bar to clear** (schematic, illustrative numbers). Bits per element for raw 8-bit storage (HiSparse), for solo coding (≈ 6.24 bits, the ideal rate of [[#homework-solo-coding]]), and for a dictionary coder whose saving over solo you set with the slider. The dictionary coder's bar has two parts: the delta, which crosses the link on every δ-miss, and the dictionary amortized over its block, $8\vw/\vb$, which is stored and kept resident but does not cross per miss. The switch applies a fixed-length code, assumed 13 % above the ideal rate. The readout gives $\vrho$ (delta only), how much smaller a miss gets compared with raw and with solo, and whether total storage beats solo.
:::

::: try
1. Leave the saving at 0.6 bit. A miss shrinks by 1.42× against raw, but only by 1.11× against solo. The second number is the dictionary's real contribution.
2. Switch to the fixed-length code. Every coded bar moves up by the same 13 %, so the ratios stay put, but $\vrho$ rises from about 0.7 to about 0.8. The engineering rate is the one that becomes the delta size of the store.
3. Raise the dictionary cost to 0.7 bit. The delta is still small, so misses still shrink, but storage now loses to solo. Light dictionaries, or big blocks.
:::

::: takeaway
- Q2 is "beat solo on the miss path", not "beat raw": solo coding already gives ~1.1–1.3× for free.
- The hurdles: the solo bar, the dictionary's amortized cost, random access with fixed-length deltas, and the 8-bit grid.
- Only conditional structure — the thing Q1 measures — can clear them.
:::

## What yes, no and partly would look like {#outcomes}

Q2 is answered by a curve, not a number: for each coder, delta size against dictionary cost ([[#questions-framework-b]]). Its outcomes are shapes of that curve.

| answer | what the curve looks like | what we would do |
|---|---|---|
| **yes, cheaply** | the best coders sit well below solo at small dictionary cost (light types: [[loc]], a low-rank basis) | lever 1 is alive with light dictionaries; residency is easy and Q3 mostly stops mattering |
| **partly: heavy only** | low $\vrho$ is reached only by heavy dictionaries (many centroids, full transforms) | the verdict moves to Q3: can heavy dictionaries stay resident? Shared prefixes might pay for them ([[#questions-parked-dictionaries]]) |
| **partly: only in the ideal column** | entropy-rate gains are real, fixed-length gains vanish | the saving needs a stream coder the miss path cannot run; report it as a measurement, and see whether [[context-modeling]] narrows the gap |
| **no** | the best curve hugs the solo line | the block idea is dead; the result is a negative measurement plus a recommendation: solo coding on the miss path |

::: note warning Where the argument is thin
The yes row assumes that light dictionaries capture most of the gain. That is what the rate–distortion napkin predicts for bell-shaped data ([[#homework-vq]]), and what the synthetic rehearsal showed ([[#homework-rehearsal]]). If real KV entries form tight clusters, heavy codebooks win instead, and the cheap path closes. Only the measurement can tell.
:::

::: takeaway
- Q2's outcome is a curve: where the best coders sit relative to solo, and at what dictionary cost.
- Cheap and below solo: build it. Heavy only: ask Q3. Ideal only: a measurement, not a system. Hugging solo: publish the negative.
:::

## Where Q2 plugs in {#links}

- **From Q1.** Q1 says how many bits exist; Q2 asks how many survive the trip into a store that the miss path can read. A positive Q1 with a negative Q2 is possible: bits that only a slow stream coder can harvest.
- **Levers.** Q2 produces the delta ratio $\vrho$ of [[lever]] 1 directly, and decides whether deltas are fixed-length — which lever 2 and the [[victim-tier]] both need.
- **Access pattern.** The hurdles of the form factor come from how misses are read, not from the statistics of the data ([[#idea-data-layout]]).
- **Frameworks.** [[#questions-framework-b]] finds the best coder; [[#questions-framework-d]] checks that the saving survives into requests per GPU.

::: takeaway
- Q2 converts Q1's bits into the $\vrho$ of lever 1, under the miss path's rules.
- Framework B answers it with a curve; framework D prices it.
:::
