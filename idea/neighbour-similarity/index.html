IV.7

Neighbour similarity

The idea is only as good as a property of KV caches that nobody has measured at 8 bits. Before measuring it, name it carefully — an imprecise name already caused one real mistake in the first draft.

In the first drafts of this proposal one word, “locality”, was used for two different things. One was that the indexer keeps choosing the same past positions. The other was that nearby entries hold similar numbers. Evidence for the first was then quoted as evidence for the second. IV.13 The leak: hit rate is about queries shows why that does not work. This page and the next three give the two things different names, so that the mistake cannot happen again.

Three properties, two kinds

The idea leans on three properties. One is about which entries are wanted. Two are about what is inside them.

  • ① The Lucky Louis property — established. The cache bets on last round’s winners and keeps winning (III.8 The Lucky Louis property).
  • ② Fallen-apple similarity — a hypothesis, and the one the project exists to measure first (IV.8 Fallen-apple similarity).
  • ③ Upstairs similarity — a hypothesis, second priority (IV.9 Upstairs similarity).

The design needs ① in a stronger, per-block form as well (IV.10 Lucky Louis, block by block). It needs ② for its deltas to be small at all.

Running themeWhich entries, versus what is inside them

This is the page where the distinction is made. ① lives in the queries: how the hidden state moves from one step to the next. ② and ③ live in the stored bytes. One can hold without the others, in both directions.

Also on II.21 · III.8 · IV.8 · IV.13 · V.2 · V.14 · VII.2 · VII.12 · VII.16 · VIII.4 · VIII.10 · IX.10 · X.1
Takeaway
  • One established property about which entries are wanted (Lucky Louis).
  • Two hypotheses about what is inside them (fallen-apple, upstairs).
  • Never quote evidence for one kind as evidence for the other.

The umbrella: neighbours along an axis

The KV cache of one request is a tensor with four axes: layer l, head h, token position t and channel c — as in K[l,h,t,c]. An entry El,t​ takes everything at one layer and one token: all heads, all channels, keys and values. So two entries can be neighbours in two directions, along the token axis or along the layer axis.

neighbour similarity“the Neighbours”this project's own words
  • What it is: the family of hypotheses that an entry costs fewer bits to store exactly when a neighbouring entry along some axis of the KV tensor is already known.
  • Members: fallen-apple similarity — neighbours along the token axis, same layer (IV.8 Fallen-apple similarity); and upstairs similarity — neighbours along the layer axis, same token (IV.9 Upstairs similarity). A third member, along the head axis, would compare slices inside one entry; we do not pursue it.
  • Easy to confuse with: the Lucky Louis property, which is about which entries the indexer selects, not about their contents.
Takeaway
  • Neighbour similarity is an umbrella: “a neighbour along some axis makes an entry cheaper to store exactly”.
  • Token axis → fallen-apple similarity. Layer axis → upstairs similarity.

Measured in bits

“Similar” is a vague word. On this site it has one precise meaning: the number of bits per element that knowing the neighbour saves. That is the mutual information between an entry and its neighbour,

I(E;neighbour)=bits to store E aloneH(E)​​−bits once the neighbour is knownH(E∣neighbour)​​,(IV.7·1)
SymbolsWhat’s in this equation (3)
I
mutual information [bits] — Bits saved by knowing one thing when describing another: I(X;Y)=H(X)−H(X∣Y). II.6
E
entry — One entry as a vector of d numbers: El,t​ is token t at layer l. III.3
H
entropy [bits] — Average surprisal: the fewest bits per symbol any lossless code can average. II.4

estimated in practice as the drop in lossless code length when the coder is allowed to see the neighbour.

ReminderMutual information

H(X∣Y), the conditional entropy, is the average number of bits still needed for X once Y is known; it is never more than H(X) on average. The difference is the mutual information I(X;Y) — redundancy, similarity and predictability are three names for this same number of bits (II.6 Mutual information).

Why bits, and not the measures that papers often report?

  • Cosine similarity says two vectors point the same way. It can be close to 1 while most elements of the two entries are unrelated — a few large channels can dominate it. Lossless coding pays for every element. IV.8 Fallen-apple similarity shows a concrete case.
  • Perplexity is 2H over tokens of text. It is the right unit for a language model’s predictions, not for the numbers stored in its cache.
  • Bits convert directly: bits per element × elements per entry = bytes per entry, and bytes per entry is what crosses the link on every miss.
Running themeBits are the unit

The property the project bets on is defined as a number of bits, so that a measurement of it converts directly into ρ — the delta ratio — and from there into bytes on the link.

Takeaway
  • Neighbour similarity is measured as bits saved: H(E)−H(E∣neighbour), per element.
  • Cosine similarity and perplexity do not convert into bytes; bits do.
